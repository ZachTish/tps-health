# TPS Health 0.14.1

TPS Health 0.14.1 keeps live workouts stationary while editing and restores the Daily Note to one workout surface.

## User-visible fixes

- Reps, weight, rest, performed state, and other live set changes preserve the current Live Preview viewport instead of jumping to the top of the Daily Note.
- Starting a workout creates only the bounded `## Workout` section. Health no longer asks GCM to create a second time-tracking workspace under `## Scheduled` or another configured heading.
- The workout card continues to show elapsed time and progress from Health's durable `startedAt` and set state.
- An active workout inherited from an older release safely detaches its one matching GCM timer and removes the empty generated workspace while retaining the workout, sets, surrounding note content, non-empty notes, other Scheduled records, and unrelated timers.

## Compatibility and migration

- No settings migration.
- No note-schema migration.
- No public API change.
- Minimum supported Obsidian version remains 1.12.0.

## Validation

- Final declared suite: 178 of 179 checks passed; the only skip was the credential-gated live USDA check.
- Focused behavior coverage verifies minimal CodeMirror range replacement with its mapped scroll snapshot, zero new GCM timer calls, one Workout heading with no Scheduled workspace, safe active legacy-timer detachment, empty-workspace cleanup, preservation of non-empty timer notes and other Scheduled sessions, and unchanged bounded workout/set mutations.
- The mandatory separate production-mode build was byte-stable after deployment to the isolated test runtime. Source and runtime `main.js`, `manifest.json`, and `styles.css` are byte-identical.
- UI reload was intentionally not attempted because the only open Obsidian window was the production vault. The safety guard prevented test automation from operating there.
- Production was not changed by this release workflow.
