# TPS Health 0.37.0

TPS Health 0.37.0 fixes a Reading-mode workout virtualization regression and makes Health-owned native-record frontmatter configurable without creating duplicate semantic fields.

## User-visible changes

- Native workout UI now mounts inside Obsidian-managed Reading-mode preview sections, so scrolling and preview virtualization no longer remove the workout card.
- **Integrations & advanced → Health record frontmatter** now exposes kind values for food entries, activity entries, workout sessions, and legacy workout exercises.
- The same panel exposes every Health-owned native log/workout property key, grouped as food/nutrition, activity, and workout/shared fields.
- Health links directly to GCM settings for the fixed shared identity, kind, title, created, and modified envelope instead of duplicating system controls.
- Custom values reject invalid slugs and collisions. Prior values changed through the UI remain readable as aliases; touched fields migrate on their next ordinary edit, while settings changes never bulk-rewrite notes.
- Health's GCM property catalog follows the configured field keys and kind values so imported properties remain scoped to the intended record types.

## Compatibility and migration

- Settings schema advances to 7. Existing default settings and records require no migration.
- Legacy Daily Note/body storage is unchanged.
- Custom kind values require a TPS Global Context Menu nativeRecords API v6 build that advertises `customKinds`; Health fails closed before writing when that capability is absent. Default kind values remain compatible with existing GCM v6 builds.
- Minimum supported Obsidian version remains 1.12.0.

## Macros plugin architecture assessment

The Macros community plugin was reviewed as an architecture reference. TPS Health should next add a canonical micronutrient registry, separate macro/micro renderers and goals, provider quality/capability metadata, field-level evidence merging, and provider connection controls. TPS Health already has local, curated, USDA, Open Food Facts, and bounded AI routes; the recommendation is to extend that unified pipeline rather than add product-specific fallbacks. An optional FatSecret provider should use device-local SecretStorage and existing cache/rate-limit protections. No nutrition data is migrated in 0.37.0.

## Validation

- Focused native-record, property-catalog, settings-layout, settings-normalization, provider, and Reading-mode source regressions.
- Full declared test suite and a separate production-mode build against the final versioned source.
- Test-vault-only deployment; production is not accessed.
