# TPS Health 0.15.7

TPS Health 0.15.7 makes completed food logs reliable and compact in both Reading mode and Live Preview. It fixes the reported mixed rendering where a `portion` entry remained a raw Markdown bullet beside oversized polished cards.

## Changes

- Reading mode treats the matched hidden TPS Health source record as authoritative, regardless of its visible serving-unit spelling.
- Legacy visible-only recognition accepts common singular and plural food units, including `portion`.
- Live Preview widget equality includes the file path, source line number, and source text so action menus cannot retain stale row targets after edits.
- Both view modes share a compact two-line grid with the food and calories first, then serving, metric amount, and P/C/F macros.
- The action is visually 28 px and uses a 44 px coarse-pointer hit region without increasing row height.
- Long names and macro groups wrap only when their container actually needs it.

## Compatibility and migration

- Minimum Obsidian version: 1.12.0.
- No settings migration.
- No food-log Markdown migration.
- No public API removal or breaking change.

## Validation

- Focused parity coverage includes `portion`, plural-unit fallback, source-authoritative Reading rendering, Live Preview source identity, compact grid structure, and touch-target behavior.
- Full declared suite passes: 183 passed, 1 credential-gated live USDA test skipped, 0 failed.
- A separate production-mode build and byte-identical test-vault deployment pass. The final versioned runtime is reloaded before publication.
- The isolated QA note uses the long product and macro shapes from the reported mobile screenshot and is moved to `_archive` after verification.
