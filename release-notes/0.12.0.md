# TPS Health 0.12.0

## What changed

- Frontmatter-based food identification now exposes the property key and separate food, recipe, and meal values directly beneath the identification mode. Creation, updates, local recognition, search indexing, templates, and the GCM property-catalog scope all use the configured mapping.
- Added a **Quick add** food-logger tab and command for one-off estimates. A name and estimated calories/macros can be logged to a selected Core Daily Note without creating a reusable food note.
- New food-log rows snapshot the consumed serving and scaled nutrient values. Updating a reusable food note affects future logs only; historical cards and Daily Note rollups retain the values recorded when the food was consumed.
- Quick add entries use the same polished Live Preview/Reading mode rendering and consumed-time/serving adjustment flow as linked foods, without showing an invalid **Open food note** action.
- The public Health schema now lists food-log snapshot, serving-basis, and nutrient fields.

## Compatibility and migration

- This is a backward-compatible feature release using settings schema v4. Existing identity settings keep the default `kind: food`, `kind: recipe`, and `kind: meal` mapping unless the user changes it.
- Legacy `kind` and `tpsType` food identities remain readable. A touched legacy note adopts the configured frontmatter identifier; no vault-wide migration runs.
- Existing complete inline food logs are treated as historical snapshots. Incomplete legacy rows retain best-effort source-note fallback because original missing nutrients cannot be reconstructed.
- Minimum supported Obsidian version: 1.12.0.

## Validation

- 170 of 171 declared Health checks passed; only the credential-gated live USDA integration check was skipped. Behavioral coverage verifies custom identity creation/recognition/migration, GCM scope, one-off Daily Note logging without a food note, immutable rollups after source-note edits, settings inventory, and mobile CSS.
- The final production-mode artifact deployed only to the isolated test runtime and hot-reloaded in Obsidian 1.13.7. **Note library** displayed the configured frontmatter key plus food/recipe/meal values. The five-tab logger opened directly on **Quick add** with a compact two-column form, full-width review action, existing tray, and consumed-time controls all visible in a narrow modal. No Quick add was submitted and no QA note was created.
- Production was not accessed or deployed.
