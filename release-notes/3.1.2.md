# TPS Health 3.1.2

Repair older workout notes from **Workouts → Calendar properties → Apply**, even when the selected property key is already correct. Previously, applying the unchanged `scheduled` mapping returned immediately and left old `startedAt` notes unrepaired. New workout creation already respects the selected timing keys.

Calendar start, interval and interval-style changes now migrate only recognized workout sessions and legacy dedicated workouts. Food/activity entries, templates, unrelated mappings and aliases remain unchanged. Applying the current mapping repairs notes without saving settings. Already-current notes are true no-ops regardless of property order.

Backward-compatible patch; minimum Obsidian **1.12.0**. Existing confirmation, conflict detection, active-workout guard, stale-preview checks and guarded rollback remain. There is no startup migration or legacy fallback in normal reads. Activity entries retain their separate mappings. Migration may reformat YAML; bodies and identifiers are preserved. Conflicting historical notes require review rather than guessed timestamps, and a process crash cannot provide a vault-wide atomic transaction.

The adapter was restored, full indexing refreshed, and both synthetic notes archived directly from Inbox. Health settings remained unchanged after explicit plugin reload. Final runtime artifacts match the release artifacts byte-for-byte.

No outbound automation was enabled. Physical iOS acceptance remains user testing.
