# TPS Health 0.3.2

TPS Health `0.3.2` is a backward-compatible search-efficiency patch. Exercise and workout-plan searches now classify, query-filter, and materialize results in one ordered loop instead of four collection passes.

## Changes

- Exercise search retains the same archive and food-note exclusions, recognition routes, query matching, ordering, conversion, and diagnostic counters.
- Workout-plan search retains the same frontmatter/folder recognition, name/title matching, ordering, conversion, and diagnostic counters.
- Each file's metadata cache is still read once in the same vault order.
- Settings, providers, note formats, health data, and UI behavior are unchanged.

## Performance evidence

- The two searches together change from eight collection stages to two ordered loops.
- The runtime patch is net two fewer source lines and adds no cache, persisted state, fallback, helper service, timer, or listener.
- A 50,000-case randomized supported-input oracle matched the former pipelines exactly.

## Validation

- `npm test`: 119 of 120 declared checks passed; one live USDA integration check was intentionally skipped because it is credential-gated.
  - Three Home action tests.
  - Two daily-note ownership tests.
  - Ninety-eight of ninety-nine provider/food/workout tests passed; one live USDA test was skipped.
  - Nine Describe tests.
  - Seven routed-settings tests.
- Table-driven regressions verify exact result objects/order, recognition routes, counters, logs, and metadata-cache access order/count.
- A separate final `npm run build` passed and deployed only to `.obsidian/plugins/tps-health` in the isolated test vault.
- Obsidian 1.12.7 was reloaded with **Reload app without saving**; **TPS Health: Log food** registered without submitting a modal or calling a provider.
- Test-runtime `data.json` remained unchanged at SHA-256 `17bd273fc88c814d0d17336acafe9f813de58e6e4a897394ad6849c57f0a0fc0`.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- Searches still inspect the supplied vault snapshot and metadata cache; this patch intentionally adds no search index or invalidation machinery.
- Live provider behavior and mutating food/workout flows were not exercised in this nonfunctional performance pass.
