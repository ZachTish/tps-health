# TPS Health 0.25.1

## Fail-closed workout ownership

- If a saved workout ID and path each resolve to a different valid session, TPS Health now treats that pair as an explicit identity conflict. Start, Finish, Discard, and rendered workout-note controls perform no repair or record mutation until the conflict is reviewed.
- Native workout surfaces now use the same settled stable-ID resolver as lifecycle actions. Moved sessions remain recoverable, while duplicate identities, conflicting pointers, and a still-warming index remain safely read-only.
- Missing-record Finish and Discard clear stale state only when the complete persisted owner still matches. If Sync has supplied a replacement, TPS Health preserves it and reports that no workout was modified.
- Grouped active-state compare-and-swap persistence now queues local workout replacements and set-count changes that occur while persisted settings are loading, preventing an older recovery operation from erasing newer local state.

## Immediate Daily Activity state

- Daily Activity blocks subscribe directly to active-workout ownership, so Start and Finish refresh every rendered day immediately even when the workout's record date differs from the open Daily Note.
- Activity listeners and elapsed-time intervals are removed on unload, and a failed dashboard render stops its timer. The independently embeddable Macros block does not subscribe to workout state.

Existing records, settings, schemas, storage modes, commands, and public APIs require no migration. Minimum supported Obsidian remains 1.12.0.
