# TPS Health 3.2.0

Adds **TPS Health: Copy recent food log timings** to the command palette on desktop and mobile. After a slow save, copy the report before reloading Health and share it to identify the delayed stage.

**This diagnostic release does not claim to fix the reported 30-second mobile delay.** The first native save can still spend time verifying the vault through GCM. The earlier GCM concurrency change does not bypass Obsidian's serial storage queue. Device measurements are needed to distinguish that work from tray persistence and other I/O.

- Measures tray saving, reusable food-note lookup/creation, native entry creation, legacy Daily Note creation/insertion/rollup/focus, and remaining-tray persistence. Native-entry time includes GCM verification; it is not a disk-only measurement.
- Includes platform, installed Health/GCM versions, storage mode, Markdown-file count and selected-food count. Active stages remain visible while pending when the command palette is accessible.
- Keeps at most eight attempts and eighty stages per attempt in memory, including with debug logging disabled. No new setting, persisted schema, file, outbound request or migration. Reload clears the reports.
- Reports omit food names, note paths, nutrient values, note contents, credentials and error text. Clipboard failure shows a retry notice. Copying is explicit; nothing is automatically sent.
- Save ordering, draft ownership, partial failure, return values and duplicate-click protections remain. Finished means an operation returned, not that every selected food was committed; tray and individual-food timings overlap. Suspension, storage waits and other plugin work contribute to elapsed time.

Minor version for the additive diagnostic command. Minimum Obsidian **1.12.0**.

## Validation

- Focused timing/tray suite: **38 passed**. A virtual-clock 30-second native write is separated from two 1-second tray saves and a 2-second food-note lookup, without real-time sleeps. Coverage includes pending reports, bounded retention, private-error omission, preserved failure behavior, duplicate-click suppression and clipboard failure.
- Full `npm test`: **477 passed, 0 failed, 1 optional live USDA test skipped** without its credential. Existing legacy post-write failure tests also check the timing stages. Source-shape assertions were updated for the timing wrappers; no failing check was skipped.
- TypeScript and separate final production build passed. The final build reported `[runtime-deploy] target=test ... unchanged`, matching the installed artifact already tested. Explicit named Health reload loaded 3.2.0, retained the command and cleared transient reports.
- Installed test-vault API/command QA created a synthetic reusable food and native entry; half of a 200-calorie serving remained 100 calories. The report measured food-note work at **126 ms**, native-entry work at **3,689 ms**, and total at **3,815 ms** with GCM 3.2.0. The command copied the generated report; clipboard equality and absence of synthetic food name/path were verified. Physical mobile timing is not established by this desktop sample.
- Both Health and GCM persisted settings remained byte-identical. Temporary adapters and folder overrides were restored. Synthetic notes moved directly from Inbox to `_archive/QA-food-timings-20260923`. No provider calls, real food logs, settings UI changes or production access. Physical iOS QA remains user testing.

Tested in **Obsidian Plugin Test Vault**, ready for the user's **BRAT pull of 3.2.0**. Publication does not install the update on any production device.
