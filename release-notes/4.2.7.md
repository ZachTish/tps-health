# TPS Health 4.2.7

Log food searches online only when requested. This backward-compatible patch keeps local search, explicit Search/Enter and barcode routes; minimum Obsidian remains **1.12.0**.

## Behavior and ownership

Typing searches saved and built-in foods after the existing 100 ms local debounce. It no longer starts an online request 800 ms later. Restoring a food-search draft also stays local. Status text explains how to request online results with Search or Enter.

Explicit submissions retain their combined local/database search, shared request-local usage history, busy guard, stale-result protection, error handling and loading cleanup. Barcode submission and the scanner retain their existing routes. No provider, setting, schema, public API, classification, tray behavior or note format changes; no migration, cache, watcher, retry or repair layer is added.

## Regression validation

The actual-modal baseline reproduced five failures across the first ten checks on 4.2.6. Twelve new passing checks cover local-only typing, input bursts, draft restoration, composition, explicit Search and Enter, both configured providers, barcode, empty-result guidance and existing tab/close guards. The test modal executes the real input/button/timer handlers against synthetic Obsidian/DOM, catalog/history and provider boundaries.

The versioned declared suite passed **665 of 666 checks**, with zero failures or cancellations and one existing optional live USDA credential skip. TypeScript, the suite build and a separate build passed with `TPS_NO_DEPLOY=1`, leaving runtime unchanged at those gates. An ordinary build subsequently deployed only to Obsidian Plugin Test Vault (`target=test`); a Health reload loaded 4.2.7. No production installation is included.

## Installed foreground QA

With all eight active TPS consumers enabled, the actual Log food command opened its native modal. Opening and typing `apple` performed one local search, two usage-history materializations, zero online submissions and one Markdown inventory in the first flow. Repeating the flow performed the same local/history work with zero inventories. The matching 4.2.6 baseline performed two local searches, three history materializations and one automatic online submission.

The native Search button and Enter each retained one local search, one usage-history materialization and one online submission. A temporary `searchFoods` provider boundary returned an empty array to prevent outbound requests. Real online result contents, provider responses and provider latency are outside this QA. The first/repeated typing and explicit submission flows performed zero raw reads, cached reads and note-mutation attempts. The visible local status was “2 saved matches · Press Enter or Search to check online databases.”

These are foreground installed operation counts and functional UI evidence, not input-latency measurements, cold-start timings or physical iPhone/iPad/Windows acceptance. No claim is made to fix all causes of vault lag.
