# TPS Health 0.26.1

## Reusable definitions, isolated session records

- Every workout exercise now links to a permanent exercise-definition note. Exercise notes retain reusable identity, muscles, equipment, defaults, and coaching notes; the workout session alone owns exercise order, sets, reps, weights, timestamps, and aggregate results in `workoutData`.
- Legacy native import and child-note consolidation backfill missing reusable exercise links before committing or cleaning up session storage. The deprecated `createExerciseNote: false` input remains accepted but can no longer create an unlinked occurrence.
- Permanent food notes retain reusable identity, serving, nutrition, ingredient, and provider facts only. Consumed quantity/unit, amount, date/time, and immutable nutrition snapshot remain on the food-entry record.
- Custom templates are sanitized when a definition is created. Updating a permanent food or exercise also removes known consumption/session fields that previously leaked into it, without changing unrelated user properties or body content.

This is a backward-compatible data-ownership patch. Existing records, definitions, settings, and API callers require no migration, and there is no startup scan or vault-wide rewrite. Minimum supported Obsidian remains 1.12.0.
