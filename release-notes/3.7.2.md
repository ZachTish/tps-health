# TPS Health 3.7.2

Health no longer treats note opening, plugin load or metadata-index resolution as a request to rewrite legacy food logs. The former observers repeatedly scanned and processed daily/log notes, including when native-record storage was selected. The note-open path could also replace a note body using an earlier cached snapshot. This patch removes those automatic operations and their unused timer/helpers.

- Food creation and explicit edits still write the compact fields and nutrition through their existing authoring paths.
- Viewing existing legacy logs preserves their source; read-only nutrition projection remains compatible with them.
- Explicit Base repair/configuration actions and configured daily-rollup updates after food logging remain available.
- Preserves the published 3.7.1 phone/tablet form improvements.
- No new setting, watcher, cache, retry, migration, schema or API change. Minimum Obsidian **1.12.0**.

This is a backward-compatible performance/correctness patch. Other native indexing, workout restoration and cross-plugin activity are unchanged, so this release does not promise to eliminate every vault delay.

## Validation

The new regression runs actual plugin load plus 100 note-open/metadata-resolution bursts with 128 unrelated notes and a legacy daily food entry. It requires zero startup body reads/process attempts/modifications and zero settled-burst body reads/write attempts/vault scans. Running it against released 3.7.0 failed with two cached reads, one process attempt and one source modification during startup. Existing food authoring, nutrition snapshot, portion and recipe tests are retained.

- Full versioned `npm test`: **493 passed, 0 failed, 1 optional live USDA skip** without its credential; TypeScript and its production build passed. `TPS_NO_DEPLOY=1` kept the active test runtime unchanged while installed QA was coordinated.
- The separate normal build deploys only to **Obsidian Plugin Test Vault**. Named disable/enable reload verifies installed **3.7.2**. Combined installed smoke checks passed for four note opens and Calendar note creation; Health settings remained byte-identical. Lifecycle operation counts and food authoring correctness are covered by the regression suites. No live USDA request or physical iPhone verification is claimed.
- Tested in the test vault and ready for the user's **BRAT pull**. Publication does not install it in production; no direct production deployment is included.
