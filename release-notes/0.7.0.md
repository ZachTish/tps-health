# TPS Health 0.7.0

TPS Health 0.7.0 is a backward-compatible recipe/meal editing and reusable-note identity release. It keeps configured identifiers in Obsidian Properties instead of note bodies and makes ingredient replacement/removal safe and practical in narrow panes.

## User-visible changes

- New reusable food notes store the configured food tag in YAML `tags`. New recipe and meal notes store the configured recipe tag there; `kind: recipe` versus `kind: meal` remains the canonical distinction. TPS Health no longer adds the configured identifier as a standalone body line.
- Legacy notes with an old standalone body tag remain discoverable. When TPS Health updates one, it merges the normalized configured tag into frontmatter, preserves unrelated tags/content, and removes only the exact legacy hashtag preamble.
- Live Preview and Reading-mode ingredient cards now include **Replace** and **Remove** beside the existing quantity/unit controls. The full recipe/meal editor exposes the same actions plus Add, so ingredients can be changed without manually editing linked Markdown.
- Replace retains the old amount and unit when the selected food supports them. When it does not, the picker visibly adopts the selected food's supported default before confirmation. Remove updates nutrition immediately; removing the final ingredient writes zero totals and leaves Add available.
- Ingredient mutations preserve headings, instructions, link labels, section order, and unrelated active-editor changes. Exact-row validation, per-recipe serialization, stale-snapshot guards, duplicate-submit suppression, and queued nutrition repair prevent ambiguous or partly committed actions from being retried into duplicate data.
- Both rendered cards and modal rows use a compact Food / Qty+Unit / Macros / Actions layout that remains usable in split desktop panes and on touch devices.

## Compatibility and migration

- Minimum supported Obsidian version remains 1.12.0.
- Existing settings, note paths, ingredient-line syntax, food logs, plugin APIs, and BRAT installation remain compatible.
- No vault-wide migration is required. Old inline identity tags remain a supported read signal and are migrated only when TPS Health touches the corresponding reusable note.
- Daily and single-file food-log target notes are intentionally not tagged as reusable foods. Each logged line keeps its `[type:: foodLog]` body discriminator.

## Validation

- The final declared suite passed 156 of 157 checks with only the intentionally credential-gated live USDA integration check skipped: three Home, two date-owner, 136 provider checks with 135 passed, nine Describe, and seven routed-settings checks. Focused coverage includes frontmatter-only food/recipe/meal identity tags, commented custom templates, legacy hashtag migration, daily/single-file log boundaries, first-line linked-row formatting, Replace/Remove targeting, amount preservation, empty-recipe totals, GCM-first frontmatter routing, active-editor compare-and-swap, serialized nutrition repair, and invalid ingredient quantities.
- The versioned artifact deployed only to the isolated test runtime and hot-reloaded in Obsidian 1.13.7. A synthetic narrow-pane meal showed all four card rows without clipping; Replace opened with the existing `1 serving`; Remove zeroed the final ingredient and retained `+ Ingredient`; and the configured `#tps/recipe` body identifier migrated into the YAML `tags` property while body directions survived. The fixtures were moved directly from `Inbox` to `_archive`, runtime `data.json` remained SHA-256 `9339e62295b47afc8cb8b557d134297c726e87f7e55142fd63a0116a50e6860f`, and production was not accessed.

## Known limitations

- Two completely identical ingredient rows cannot be disambiguated after an external edit removes their positional context; TPS Health fails closed and asks the user to reopen/refresh rather than guessing which row to mutate.
- A legacy standalone configured hashtag is migrated when that reusable note is next updated; TPS Health does not bulk-rewrite untouched vault notes.
- Physical iPhone behavior should receive the normal on-device acceptance check after the BRAT pull.
