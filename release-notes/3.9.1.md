# TPS Health 3.9.1 — Fewer reads while displaying ordinary notes

Opening a note in Reading mode could make Health request the entire file for each ordinary list or H2 section, even when it contained no food log or workout marker. Health now checks Obsidian's section source first and skips the full-note read when that source establishes the section is unrelated. Missing or ambiguous section information keeps the existing read. Hidden-field food rows, unfamiliar serving units, repeated-row menu targets, and workout headers retain their source-based rendering.

This backward-compatible performance patch adds no setting, note migration, writer, cache, watcher, or retry. Minimum Obsidian remains **1.12.0**. It was tested in **Obsidian Plugin Test Vault** and is ready for the user's BRAT pull; production was not changed by this release.

## Validation

- All 21 focused Reading-render tests and **578 checks across 25 declared test runs** passed under `TPS_NO_DEPLOY=1 npm test`; zero failed and one optional live USDA check was skipped. TypeScript and production bundling passed. Tests cover ordinary-section read counts, full-document and section-local source text, hidden food and workout comments, repeated custom-unit rows, and null or ambiguous source fallback.
- On the same 49 KB ordinary audit note in foreground Reading mode, Health-attributed `cachedRead` calls fell from **19** on 3.9.0 to **6** with this change. Total calls fell from **36** to **8** across enabled plugins. These are operation counts, not note-open timings; the surrounding Test suite also changed independently between samples.
- A read-only Obsidian 1.14.2 probe showed that the actual section source includes hidden food and workout comments and that `lineStart` identifies each rendered element. The installed Test build still displayed a 190 kcal food chip with its action button and the workout controls. The temporary probe and QA tab were removed, and Health runtime `data.json` stayed byte-identical.

The public section-info type does not explicitly guarantee comment completeness on every Obsidian version or device. Physical iPhone rendering and end-to-end latency remain to be checked after the BRAT update.
