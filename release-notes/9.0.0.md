# TPS Health 9.0.0 — Native Bases and Canvas dashboards

Removes the standalone Health view, Open health dashboard command, ribbon icon, week-navigation adapter and dashboard-only styles. Food/activity/workout logging, reusable definitions, goals, tracked-nutrient rules, property APIs and optional embedded Health blocks remain supported. Ordinary Bases read existing records directly; this release does not change their queries or generate replacement pages.

Includes the retained, previously unpublished 8.0.1 changes: food-provider settings open directly in Health, and food/recipe searches display saved matches and completed provider results while the other provider is pending. Existing settings keys, credential references, request routes, query tokens and full-result API remain unchanged. See the historical 8.0.1 candidate receipt for its scope.

Validation: **869 tests, 868 passed, 1 optional live USDA check skipped, 0 failures**. The skipped check requires a dedicated live credential; provider tests use controlled responses. The separate production build passes. Retirement assertions verify no standalone view/launcher registration while native index, food search and logging APIs remain.

Installed acceptance: all five settings destinations inspected, direct food-provider controls visible, selected-route accessibility and narrow horizontal navigation checked. Log food, Log activity and Start workout dialogs open and cancel without creating records. In the actual installed food picker, both controlled provider arrival orders display the first result while the second is pending, then display both; no outbound requests were made. Recipe selection, cancellation, selected portions and Controller-absent setup are covered by source/host tests rather than physical-device tests. Settings data.json and enabled state remain byte-for-byte unchanged. Temporary QA configuration was restored.

Minimum Obsidian: **1.12.0**. Major version reflects removal of supported custom dashboard views and launchers. No startup migration, replacement dashboard, watcher or repair is added. Existing notes, authored Bases/Canvas, settings and private state are preserved. Close any saved obsolete dashboard tab and open your own Base or Canvas.

Validation was performed in **Obsidian Plugin Test Vault**, with Sync disabled and normal consumers enabled. The full declared test suite and a separate production build are required for the final artifacts. Final SHA-256 digests are included in the public release; exact local logs and UI receipts are retained outside the vault. Test installation, public release and production installation are distinct. This release is ready for the user's BRAT pull; production was not directly updated. No physical-phone result or performance timing is claimed.
