# TPS Health 3.9.2 — Stable Daily Note totals after metadata refresh

Macros and Activity read Health's in-memory index of saved native records. A new food or activity log enters that index immediately, but a subsequent Obsidian metadata event could remove it when the event's cache omitted frontmatter even though its source still contained the saved record. Health now uses the source supplied by that event when cached frontmatter is absent. Food and activity remain visible after the refresh; a genuinely removed or invalid record still disappears.

This backward-compatible patch adds no setting, note migration, writer, disk read, vault scan, watcher, or delayed repair. Minimum Obsidian remains **1.12.0**. Health 3.9.0 also fixed an incomplete-cache startup path, so both fixes are needed by vaults still on 3.8.8.

## Validation

- The new focused regression fails on 3.9.1 when a saved food log reverts from 210 kcal to zero after a metadata event with absent cached frontmatter. It passes on 3.9.2, also covering activity totals, legitimate frontmatter removal, and zero additional reads, writes, or scans.
- All 106 native-record tests passed. The declared full suite passed across 25 runs: 580 passed, one optional USDA test skipped, and none failed. A separate production build deployed the exact artifacts below to Obsidian Plugin Test Vault. After a Health-only reload, Obsidian reported the installed plugin as 3.9.2 and its saved synthetic food records for 2098-01-01 still indexed as three entries totaling 510 kcal. Health's test-vault `data.json` was byte-identical before and after deployment/reload. The actual iPhone widget interaction was not reproduced in the test vault.

Physical iPhone verification and the affected vault's exact event timing remain outstanding until the user installs and tests this release.
