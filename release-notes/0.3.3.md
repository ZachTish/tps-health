# TPS Health 0.3.3

TPS Health `0.3.3` is a backward-compatible GCM lifecycle reliability patch. Food-action readiness retries now reuse Health's existing owned layout lifecycle listener instead of adding another listener after every unsuccessful registration.

## Changes

- Initial GCM absence, delayed readiness, thrown registrations, and invalid registration disposers no longer multiply layout listeners.
- A successfully registered food action remains single-owned and keeps the same ID, label, icon, order, visibility rule, and click behavior.
- GCM provider removal or replacement clears stale ownership and registers once with the replacement provider.
- Registration and cleanup failures are contained so they cannot block Health's shared menu or workout-action refreshes.
- Settings, note formats, health data, providers, and food/workout behavior are unchanged.

## Before/after evidence

- Released `0.3.2` grew from 2 observed layout listeners after load to 1,025 after ten synthetic layout dispatches while GCM registration remained unavailable.
- `0.3.3` remains at one Health-owned layout listener across the same ten dispatches.
- The regression also exercises throw, invalid-disposer, successful readiness, provider removal, stale cleanup failure, provider replacement, duplicate prevention, and unload cleanup.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- Health uses the supported GCM v1 `externalActions.register()` contract. An unsupported provider that mutates its register function in place without replacing the `externalActions` object is outside this lifecycle contract.
- The intentionally credential-gated live USDA check was not run.
