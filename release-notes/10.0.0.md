# TPS Health 10.0.0

Health goals can now be adopted into editable notes and compared with food totals in ordinary Obsidian Bases. This major version changes the canonical goal storage after explicit adoption; settings schema 10 blocks older Health settings writers. Obsidian 1.12.0 is the minimum.

## Behavior and migration

- Food & goals exposes Move goals to notes, Open goals Base and Open food comparison.
- Adoption preserves effective targets, labels, units, colors and display choices. Goal notes then own tracking/targets. Legacy goal arrays and scalar targets are removed from persisted settings; unrelated settings/private state remains unchanged.
- Health Goals is an editable native table. Food & Goals uses native table formulas/summaries, combining current goal rows and today's food rows. Target edits, goal renames/moves and food changes require no Base regeneration.
- Minimum, maximum, range and track-only goals are supported. Missing nutrients remain unknown; duplicate goals, invalid bounds and changed units cannot silently claim success.
- Existing Bases are opened unchanged. The old inline Food Log Base generation/repair code and custom goal JSON editor are removed. Earlier inline logs remain untouched/readable.
- There is no startup migration, additional vault scan, background writer or copied target/rollup. Goal metadata uses existing Health discovery and events.

## Limits

- The initial comparison has columns for nutrients tracked when it is created; additional metric columns are an explicit Base edit. Activity goals remain separate from the food comparison.
- Current targets are recurring, not historical effective-date snapshots.
- An older-device runtime must be updated/reloaded; desktop acceptance does not establish physical iPhone acceptance.

## Validation

- Full declared suite: 884 tests, 883 passed, one optional live USDA credential check skipped, zero failures. A separate TypeScript/esbuild build passed.
- Explicit test-vault deployment/reload: loaded 10.0.0, Health enabled, Obsidian Sync disabled. Real settings buttons adopted seven synthetic/default goals, saved a protein target and opened both native Bases. Only the QA destination arguments were redirected into Inbox.
- Native installed Base: adding a synthetic food note produced 400 kcal and 74.5 g protein; renaming/moving its goal and changing 150 to 160 g updated the open summary to 85.5 g below minimum. Missing protein reported incomplete; an incompatible unit reported Invalid goal. The Base remained byte-identical with zero modify events. Targets/display defaults were restored.
- Five settings destinations inspected; desktop and 600-pixel-wide window captures confirm the goal buttons, wrapping and stacked layout. No provider request or outbound integration was enabled.
- Reload regression: linked food display never consults mutation/goal readiness; goal indexing completes after reload with all seven notes restored. Explicit food writes retain their readiness guard.
- Projection regressions count unchanged events and bursts: no added scans/body reads/goal notifications for unrelated edits; actual goal changes, rename/delete and duplicate/invalid input are covered. Source-boundary tests cover concurrent settings/goal changes and unsaved editors.
- Test-vault adoption removes four goal authority keys plus the pre-existing save normalizer's eight already-retired keys. Active unrelated settings are unchanged; backups/receipts remain outside the vault. Actual effective targets are preserved.
- Synthetic food insertion used the Vault API with the real GCM classification/identity encoder; this test vault's food writer is unconfigured. No claim of a new installed food-picker/provider acceptance or physical iPhone test. Existing logging regression suites passed.

Tested in the test vault. Publication and production installation are recorded separately; no user-acceptance/production-ready claim.
