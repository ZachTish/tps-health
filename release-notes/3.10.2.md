# TPS Health 3.10.2 — Skip no-op reads on daily navigation

Macros-only blocks no longer resolve the active workout while rendering food totals. Activity and combined dashboard blocks still resolve it, including Resume and Finish controls for an active session. When the GCM food-log action is disabled, Health still asks GCM to refresh its menus and hides a stale food button, but skips Daily Notes date-context and diagnostic settings reads. An enabled action still appears on a recognized Daily Note; disabling it during an in-flight context lookup leaves it hidden.

This is a backward-compatible performance patch. It changes no note format, setting, command, GCM API or migration behavior and adds no cache, watcher or retry. Minimum Obsidian remains **1.12.0**. Physical iPhone performance and installed navigation operation counts were not measured. This release was tested in **Obsidian Plugin Test Vault** and is ready for the user's BRAT pull; production was not modified.

## Validation

- In a focused synthetic 10,000-workout regression, a Macros render previously resolved the active workout once and visited 10,000 records; it now makes zero resolutions and zero visits. Activity still resolves once, visits the history and shows Active Lift with Resume and Finish controls.
- In 20 disabled GCM refreshes with Core Daily Notes settings unavailable, the prior path read `.obsidian/daily-notes.json` 40 times; the changed path reads it zero times while scheduling all 20 GCM menu refreshes and hiding a stale action. An enabled action still reads its date and diagnostic context twice and appears on a valid Daily Note. Disabling the setting during an awaited lookup hides the button without a further diagnostic read. The harness made zero writes. These are source-test operation counts, not installed-phone timings.
- The versioned declared `npm test` suite ran 606 checks: 605 passed, zero failed, and one optional live USDA check skipped without its credential. TypeScript and a separate final `npm run build` pass. The suite build deployed only changed Health `main.js` and `manifest.json` into the test-vault runtime; the separate build was byte-identical.
- In the exact `Obsidian Plugin Test Vault` window, Obsidian's plugin registry was refreshed and Health was reloaded. The loaded plugin object reported `manifest.version` **3.10.2**. The Health dashboard rendered for October 2, 2026, and the existing archived Macros QA note displayed 210 kcal, 12 g protein, 27 g carbs and 6 g fat. Health runtime `data.json` remained byte-identical. QA made no note or plugin-setting edits and no outbound provider calls.
