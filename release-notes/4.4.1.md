# TPS Health 4.4.1

Workout controls can disappear when Obsidian recycles a Reading section or initializes a Live Preview editor. This patch corrects those rendering owners so a valid indexed workout keeps its controls without changing its note.

This is a backward-compatible patch. Minimum Obsidian remains **1.12.0**. Settings schema 9, configured kind/property mappings, record identity, active-session state, recovery controls and note data are unchanged. No migration is required.

## Fixes and ownership

- The existing Reading observer recognizes removal of a wrapper containing the workout surface and arrival of a wrapped footer. It notifies the existing coalesced mount owner. This includes the managed-section fallback used when there is no footer or body postprocessor section.
- Live Preview widgets use Obsidian’s public `editorLivePreviewField`, rather than a host CSS class that can arrive later. Early or detached hosts no longer turn the widget into a permanently empty span; a stale class cannot show workout UI in literal Source mode.
- The existing editor field compares the widget’s captured file path with the current public editor context on otherwise ignored transactions. Obsidian can initialize or mutate that context in place; comparing two references to it would miss the change. Late initialization and identical-text note transitions now update the owning decoration. Normal typing retains its existing fast branch, and unchanged transactions retain the same decoration object.

The path resolver reuses constant-time indexed membership. The field owns at most one workout widget. There is no new watcher, timer, poller, scan, source read, mutation, forced editor replay or repair route. Ordinary paragraph changes, card internals and the card’s own insertion do not schedule Reading refreshes. Structural changes reuse the existing 80 ms debounce.

## Regression evidence

The actual released 4.4.0 observer schedules zero refreshes after its containing workout section is removed; the corrected observer schedules one. The actual released editor functions fail five race/ownership checks: early host class, detached host, stale Source class, late mutable file context and identical-text file transition. The corrected editor passes all eleven lifecycle checks.

The **93 focused Reading/editor/surface checks pass**. Five Reading lifecycle tests execute the actual observer callback, scheduler and mount/index projection. Six editor checks execute the actual widget, public state fields and transactions. Host DOM, scheduling and final-render boundaries are synthetic where stated; there is no Obsidian process or vault I/O in these source harnesses.

Five hundred ordinary Reading mutation deliveries schedule no work. Twenty structural deliveries retain one pending refresh. Five hundred ignored editor effects in each ordinary, Source and uninitialized context retain their decorations without snapshots, renders or external refresh dispatches. Existing disposal tests retain native-surface refusal; the structural-burst test stubs action-bar updating and does not independently prove all shutdown behavior.

Final versioned declared suite: **804 passed, zero failed, one existing optional USDA credential skip, 805 total**. TypeScript and the suite build pass with deployment suppressed; a separate ordinary production-mode build deploys only the test runtime. An obsolete source-shape assertion was updated to the public editor-mode authority and retains the existing integration checks.

## Installed test-vault verification

QA ran in the foreground **Obsidian Plugin Test Vault**, Obsidian **1.14.4**, with all eight active TPS consumers and upstream Navigator enabled. No outbound provider/import automation was enabled. It used one synthetic frontmatter-only session created by the actual Health/GCM creation owner, with temporary in-memory configured list classification `kind: [transaction/workout]` and an isolated Inbox destination. The active pointer was also temporary in-memory QA state; no real workout was resumed or changed.

The installed 4.4.0 Reading observer was tested by nesting the mounted card in a removable preview wrapper. Removing it scheduled **zero** refreshes and left **zero** cards. Source remained byte-identical. The final 4.4.1 artifact was deployed and reloaded by disabling/enabling only Health. The same structural removal scheduled **one** refresh and retained **one** active card, again with unchanged source. A 250 ms observation window was used; it is not a measured remount latency or mobile performance claim.

Installed actual Live Preview widgets render with the host class absent and with a detached host. Literal Source shows no card. The first fresh editor shows one card at the first observed readiness frame (**76 ms**); eight warm Reading/Live Preview switches each retain one card (**8–15 ms**). These are foreground synthetic-session component measurements, not full cold-start, production, physical-phone or before/after speed measurements. The warm switches attempt **zero raw reads, cached reads, writes or Markdown inventories** through the instrumented vault APIs; direct adapter/core I/O is outside those counters. Five hundred ordinary DOM paragraphs schedule no Health refresh. Narrow mounted controls were visually inspected, including Add Exercise and Finish.

The first scripted mode check incorrectly called `MarkdownView.setState` without its host result argument; QA was corrected to use Obsidian’s `WorkspaceLeaf.setViewState`. The subsequent missing stored decoration versus current initializer result provided the additional file-context invalidation evidence. Final mode checks use the leaf lifecycle without forced transactions or external decoration replays.

All transient methods, classification/destination and active settings were restored, diagnostics closed, and the prior test view restored. The fixture was moved directly to `_archive/Workout UI QA 20261010` byte-identically. Captured saved Health/GCM/Controller/Calendar/Finance/Linter/Navigator settings hashes remained unchanged. No production inspection, deployment or note remediation was performed.

## Limitations and handoff

This fixes demonstrated rendering gaps for eligible indexed workout sessions. It does not change classification, resolve ambiguous identities, invent missing session data or rewrite status values. A mutable file-context change is observed on the next normal editor transaction or existing navigation/index refresh; this adds no separate notification mechanism. Physical iPhone acceptance remains to be checked after the user’s BRAT update. No guarantee is made about every possible cause of an unavailable workout record or about production startup speed.

The numeric **4.4.1** public release is the tested BRAT handoff. Update TPS Health with BRAT on each device; production installation remains separate from this test-vault release.
