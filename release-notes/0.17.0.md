# TPS Health 0.17.0

TPS Health 0.17.0 prevents accidental duplicate saved foods, gives the user an explicit safe collision decision, and removes the visible HTML identity comment from the Daily Note workout task.

## Changes

- Custom-food and barcode-review saves now show possible saved matches by canonical barcode, compatible exact name, or direct name/alias match.
- The duplicate review offers **Use existing**, **Combine into existing**, **Keep separate**, and **Cancel**, with the candidate's path, serving, and macros visible before the write.
- **Use existing** leaves the selected note unchanged. **Combine into existing** preserves its path, local identity metadata, aliases, and notes while applying the reviewed serving and nutrition as one coherent pair. **Keep separate** is the only choice that intentionally creates another note. No review action deletes a note.
- Reusable food-note writes now share one catalog mutation queue and recheck saved candidates after earlier work completes. This prevents concurrent manual, barcode, label, logging, and API requests from racing into duplicate files.
- The public create/upsert food inputs accept `duplicateStrategy: "reuse" | "combine" | "create"`. Direct creates default to safe reuse; existing upsert callers retain their historical behavior when the field is omitted.
- New workout navigation tasks use `[kind:: workout] [workoutId:: …]` inline fields instead of a trailing `tps-health:workout-task` HTML comment. The protected session boundary comments remain unchanged.
- Legacy workout task comments remain readable. Repair migrates them to inline identity and preserves an existing GCM `tpsId`.

## Compatibility and migration

- There is no settings migration and no bulk rewrite or deletion of existing food notes.
- Historical food logs retain their nutrition snapshots and existing links. Combining updates the selected reusable note for future resolution without rewriting old logs.
- Existing duplicate notes remain separate until the user encounters and resolves a matching save; TPS Health does not guess which existing file should be deleted or relinked.
- Legacy comment-based workout tasks continue to match active GCM timers and migrate only when TPS Health repairs that workout block.
- Minimum supported Obsidian version remains 1.12.0.
