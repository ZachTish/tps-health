# TPS Health 3.9.0 — Fixed TDEE and complete startup food index

Health could show “No food logged” for a day with valid food notes. When Obsidian marked metadata initialized before every file cache was available, Health's first scan omitted those notes but marked the index settled. The next metadata-resolution event now makes one reconciliation pass and notifies open day views. Ordinary later metadata events keep the incremental path; this adds no poller, note rewrite, or background repair. Workout-body hydration waits for that reconciliation, and Finish and Discard preserve the active pointer if its file exists but its metadata record has not loaded.

This release also preserves the fixed/calculated TDEE selector and inactive-input save fix already installed as the unpublished 3.8.9 Test-vault candidate. Fixed mode uses the entered kcal/day full-day target; Calculated retains BMR × activity factor. An invalid fixed target remains unavailable rather than silently using a different estimate. The TishOS Daily Fitness widget needs its companion update to read the selected method. Existing note schemas and Health settings need no migration.

This is a backward-compatible minor release because the fixed-TDEE setting is new to the public release. Minimum Obsidian remains **1.12.0**. It was developed in **Obsidian Plugin Test Vault**; production installation is the user's BRAT step.

## Validation

- **571 passed, 0 failed, 1 skipped** across 25 declared test runs under `TPS_NO_DEPLOY=1 npm test`. The skip is the optional live USDA check requiring credentials. TypeScript and production bundling passed; the build reported `[runtime-deploy] target=none`.
- The startup regression reproduces an empty and a partially cached tagged-food index, then verifies the next metadata resolution restores totals and announces the affected day. Fifty subsequent settled `resolved` events cause no further vault scans; the tests observe no body reads or writes.
- The carried-forward TDEE tests cover both modes, target validation, normalization, saved inactive inputs, and settings-save rollback. Workout regressions cover deferred hydration after incomplete startup and preserving the active pointer on Finish and Discard while its file is present but unindexed.
- The separate final build deployed `main.js` to the Test vault. A targeted reload loaded Health 3.9.0 without changing its `data.json` hash. A canonical synthetic food note for September 30 was classified by the installed GCM, indexed as one entry with 123 kcal, and displayed in the Health dashboard. After setting `archived: true` and moving that note directly from Inbox to `_archive`, the index returned to zero entries. No provider request or production mutation was used.

The affected iPhone's exact metadata startup sequence was not captured. A read-only production check found valid September 30 food notes with the expected tags and nonzero nutrition, while the live Health index was empty and reported settled. Physical iPhone acceptance remains to be checked after BRAT installation.
