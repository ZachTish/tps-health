# TPS Health 0.24.2

## Reliable Daily Note ownership

- Health now delegates Daily Note creation to GCM's authoritative v2+ API whenever GCM is enabled. A starting, incompatible, failed, or declining GCM provider fails closed instead of falling through to a second creator.
- When GCM is absent or disabled, Health resolves one coherent Core Daily Notes folder/format/template snapshot, supports nested filename formats, and keeps the ISO provider contract ASCII even under localized Moment digits.
- Same-day fallback callers share one creation lifecycle. Health passively waits for Templater's delayed create hook and never executes template syntax found in a mature note. An unchanged failed owned creation receives a hidden EOF marker through an atomic byte check, so it stays fail-closed after reload/Sync without deleting the file or breaking leading YAML; externally changed collisions remain untouched.
- Legacy food and activity body writes now serialize per Markdown file, so concurrent logs re-read the preceding commit and neither entry is lost.
- Native Health records, readable native filenames, stable IDs, settings, and public APIs remain backward compatible.

Minimum supported Obsidian remains 1.12.0. GCM 1.43.2 is recommended for strict root-vault Daily Note identity; Health continues to require only Daily Notes API v2 when GCM is enabled.
