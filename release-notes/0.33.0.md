# TPS Health 0.33.0

TPS Health 0.33.0 moves native workout performance data out of hidden note-body comments and into one compact, nested, Bases-queryable `session` frontmatter property.

## Changes

- New workout notes start with one `session` object containing the ordered exercise/set graph.
- Nested exercise keys are concise (`name`, `exercise`, optional `superset`); nested set keys include only applicable values such as `reps`, `weight`, `unit`, `rest`, `type`, `drop`, and `completed`.
- Set/exercise counts, reps, volume, and timer summaries remain derived instead of becoming extra top-level properties.
- Session structure and semantic state are committed in one atomic frontmatter transaction with conflict retry and stable-set idempotency.
- Existing hidden body-marker and legacy `workoutData` sessions remain readable. Their next normal workout edit writes `session` first, then removes the exact old body comment.
- Reusable exercise notes remain definition-only; session performance stays in the owning workout note.

Example Bases formulas:

```yaml
formulas:
  exercises: 'session.exercises.map(value.name).join(", ")'
  planned_sets: 'session.exercises.map(value.sets).flat().length'
  completed_sets: 'session.exercises.map(value.sets).flat().filter(value.completed).length'
```

## Compatibility and migration

- Backward-compatible minor release; minimum Obsidian version remains 1.12.0.
- Native-record service version is 4; TPS GCM nativeRecords API v6 remains required for native storage.
- No settings migration is required.
- Obsidian's normal Properties editor does not edit nested objects. Health owns `session`; inspect it in Source mode or query it through Bases.
