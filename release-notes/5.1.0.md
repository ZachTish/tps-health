# TPS Health 5.1.0 — Consistent food search

Food logging and recipe ingredient search now share relevance-first ordering, up to 30 results, and the same source/serving detail formatter.

Exact names or aliases come first, followed by complete query-word matches. Created foods take precedence within the same relevance group. Usage cannot lift a weaker match above a stronger one. Substring matches no longer count as exact words. Existing nutrition, deduplication and explicit online-search configuration remain unchanged.

Changing a recipe query releases the previous online request state. Late results from that request cannot replace the current results or leave Search online disabled.

This additive search improvement is a minor release. Minimum Obsidian: 1.12.0. No settings or note migration. GCM native-record requirements remain unchanged.

Validation: full npm test, separate production build, test-vault deployment and targeted plugin reload. Foreground Mac QA confirmed the same four oats results in the same order in both dialogs, with created foods first. No food or recipe was saved during QA. Automated tests cover exact-vs-saved relevance, equally relevant created foods, substring matching, and stale recipe requests. The optional live USDA test is skipped; online provider response quality and physical iPhone QA are not claimed. Production installation is the user's BRAT pull.
