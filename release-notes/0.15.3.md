# TPS Health 0.15.3

TPS Health 0.15.3 fixes the exercise-picker stall observed when adding an exercise to a running workout.

## What changed

- Configured workout, workout-plan, exercise, food, and recipe folders are canonicalized without leading, trailing, or repeated slashes.
- Exercise-note creation independently canonicalizes its destination before creating the folder or file, so a setting such as `_assets/exercise/` produces `_assets/exercise/Bench press.md`, never `_assets/exercise//Bench press.md`.
- The exercise picker builds a reusable catalog in chunks of 40 Markdown files and yields between chunks so Obsidian can repaint and process input.
- Concurrent picker searches join one catalog build. Subsequent keystrokes reuse it until a relevant vault or metadata change invalidates the index.
- Search order, exact matching, exercise-note creation, archive exclusion, and food-note exclusion remain unchanged.

## Diagnosis

- The released 0.15.1 build was installed in production when the failure occurred.
- The production exercise folder was configured as `_assets/exercise/`, while the old write path appended another `/` without canonicalizing it.
- The failed attempt left the active Daily Note's bounded workout block intact with zero set rows and did not create the destination exercise folder, placing the stall before the Daily Note mutation.
- The isolated 0.15.2 test-vault flow worked with its canonical folder, confirming the fault depended on production configuration rather than the bounded workout writer.

## Compatibility

- Minimum Obsidian version: 1.12.0.
- No API or note-schema migration is required.
- Folder values with redundant separators are normalized on the next settings normalization/save.

## Validation

- Focused regressions cover the production-shaped trailing-slash setting, an 85-file catalog that yields twice, cache reuse without repeated metadata scans, canonical exercise-note creation, existing active-workout insertion, and exact lookup behavior.
- The full declared suite passed 181 tests with one credential-gated live-USDA skip and no failures. The separate production-mode build and isolated test-runtime deployment also passed.
- Final UI verification used the deployed 0.15.3 artifact in the test vault: a blank workout opened the exercise picker responsively, a newly named exercise was created and inserted without freezing, and the workout controls remained usable. The synthetic workout was discarded and its exercise note was moved to `_archive` afterward.
- The deployed `main.js`, `manifest.json`, and `styles.css` match the validated source artifacts byte-for-byte. The test runtime's existing `data.json` retained its pre-task SHA-256 hash, `b818c3ec61d14a80330ee8340e9265ca76b53d316b879a0298bc9213093e0853`.
- Production was inspected narrowly for diagnosis but was not modified, deployed, or reloaded.
