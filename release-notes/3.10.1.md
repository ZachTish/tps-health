# TPS Health 3.10.1 — Read only legacy workout bodies on startup

Once workout metadata and the layout are ready, Health reads a workout note body only if its indexed frontmatter lacks a nested `session` property. Modern sessions already contain their exercise and set graph in that property, so opening Health no longer schedules a redundant `cachedRead` for each one. Legacy body-backed sessions still hydrate after layout. A later metadata edit to a modern session updates its displayed sets from frontmatter without a body read.

This is a backward-compatible performance patch. It changes no note format, setting, command, GCM API or migration behavior. Minimum Obsidian remains **1.12.0**. Physical iPhone startup and performance remain unverified. This release is tested in **Obsidian Plugin Test Vault** and ready for the user's BRAT pull; production has not been modified.

## Validation

- The startup regression uses 128 modern sessions and one legacy body. Before the fix, startup made 129 cached body reads; after it, startup makes one (the legacy note), with zero raw reads and zero writes. Both formats retain their correct sets. A modern metadata edit changes a set from 5 to 9 reps with no further cached or raw read; 20 settled metadata events also add no reads or writes. These are test-operation counts, not physical-device timing claims.
- The declared `npm test` suite passed 604 checks: 603 passed, zero failed, and one optional live USDA check skipped without its credential. TypeScript and a separate final `npm run build` pass. The suite build deployed Health `main.js` and `manifest.json` to the test-vault runtime; the separate build was byte-identical. After an Obsidian app reload, Community plugins lists enabled TPS Health **3.10.1**, the Health dashboard opens and renders for October 2, 2026, and the existing archived Macros QA note displays 210 kcal, 12 g protein, 27 g carbs and 6 g fat. Runtime `data.json` remains byte-identical. No food/workout records or plugin settings were edited for QA.
