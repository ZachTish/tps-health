# TPS Health 4.2.1 — Scope Health properties to GCM kinds

GCM imports Health's reusable-note property definitions for its custom property menu. Under GCM kind API v2, those definitions now use GCM's current food, recipe, meal, exercise, and workout-plan classifications. A vault using a Kind list no longer imports a stale `entityKind: food` condition that matches none of its food notes. Configured tag and scalar classifications are also reflected in the catalog. Health's pre-v2 identification settings still govern the catalog when the v2 API is unavailable.

This backward-compatible **patch** changes only exported catalog scopes. It adds no setting, note rewrite, migration, background scan, or automatic re-import. Existing imported GCM property definitions retain their saved scopes until the user explicitly re-imports Health properties; re-import after changing GCM's mappings. GCM's current scope format cannot represent an OR of multiple distinct multi-property legacy classifications, and Health now reports that unsupported configuration rather than returning a misleading scope. Minimum Obsidian is **1.12.0**.

Its Note library settings showed the GCM kind-configuration handoff, with Health's legacy identity controls absent under API v2. The installed runtime `data.json` stayed byte-identical. Catalog behavior was verified through focused source/API tests; no real GCM property import or vault-note mutation was needed for this nonvisual export change.
- This release is the public BRAT handoff after Test Vault validation; it is not an installation into the production vault. Physical iPhone behavior is unverified.
