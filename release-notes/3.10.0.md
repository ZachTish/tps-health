# TPS Health 3.10.0 — Fast daily views and reliable block startup

The daily-note Macros block no longer waits for a second Daily Notes config-file read before mounting. Health registers its blocks and completes startup before the first persisted-config read, so a slow read cannot leave the plugin uninitialized. When Core Daily Notes supplies format and folder, blocks mount immediately and skip that read. If Core settings are unavailable, a block without an explicit date shows a loading message until the single persisted-config read resolves. New mounts also honor Core folder or format changes made while Health is running. During initial native-record hydration, blocks show loading instead of a false zero. Known saved totals remain visible with an indexing notice if other note caches are still unavailable; a truly empty day shows zero once indexing settles. Saved food records are unchanged.

Daily food, activity and workout queries use day buckets within the existing native-record index, reducing the work of seven-day dashboards as history grows. Create/edit/archive/rename/delete, food projection and provider changes keep those buckets current. Activity creation now uses GCM's fresh-create path and retains its generated identity. Phone-width dashboards show compact scrollable quick actions and labeled day cards for the seven-day comparison; desktop keeps its table. The seven-day comparison displays known entries with an indexing notice while other note caches remain unavailable, without claiming an empty week prematurely.

This is a backward-compatible mobile UX and performance feature with no note/settings migration, repair, watcher or poller. Minimum Obsidian: **1.12.0**. Tested in **Obsidian Plugin Test Vault** for the user's BRAT pull; production has not been modified.

## Validation

- Focused macro startup regressions cover a stalled first config read, the redundant second-read blank path, and Core settings changed between mounts. Native-record regressions cover ten-year-sized history, changed days and operation counts; the 10,054-record fixture uses 26 indexed-record lookups for seven days, zero full-kind materializations and no source I/O.
- Readiness regressions cover late provider and metadata availability, a true-zero day, 256 permanently unavailable unrelated caches, warm public-cache coverage, and partial known totals without a false zero.
- Full declared suite: 603 tests, 602 passed, 0 failed, 1 optional skip. The separate final `npm run build` passed and reported a byte-identical test deployment. A full Obsidian reload in the test vault reopened the archived synthetic daily-note fixture with its saved 210 kcal, 12 g protein, 27 g carbs and 6 g fat. The test runtime `data.json` was unchanged.
- Narrow-panel dashboard layout is covered by the dashboard view and CSS regressions. Physical iPhone acceptance and the affected phone's exact lifecycle trace remain unverified until BRAT installation and on-device testing.
