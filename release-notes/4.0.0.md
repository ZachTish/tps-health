# TPS Health 4.0.0 — Whole-note Health records

New food, activity, and workout logs now use individual Markdown records. A workout owns its exercises and sets in one session note; the Daily Note can still display saved records through the existing Macros, Activity, Daily, and Overview blocks. The old food, activity, and workout line-writing choices and Daily Note workout placement controls are gone. The remaining Workout controls choice, **In workout card** or **In floating note bar**, changes only where actions appear on that whole-note workout.

Earlier inline records remain in their original notes. Health does not scan for or import them on startup. **Daily logging → Health records** offers an explicit preview and copy action; copying creates whole-note records without deleting the lines. A saved `storageMode: legacy` displays a warning until the user explicitly chooses **Mark reviewed**. Copying alone does not clear it, because a partially imported workout may require manual inspection. Existing native-record settings continue to work immediately. Historical food lines remain visible in Live Preview and Reading mode, with read-only log actions and source navigation. Earlier active inline workouts are preserved for manual review and cannot be extended, finished, or discarded by Health.

This is a **major** release because line-level storage settings and writers are retired and the public `app.tpsHealth.updateDailyRollup` method is removed. The plugin's internal `updateDailyRollup` entrypoints now fail clearly, while `getDailyRollup` remains a read-only historical inline-food query. No active TPS plugin source in this test workspace calls the removed API. Integrations should use native daily record totals. Minimum Obsidian remains **1.12.0**.

## Validation

- Focused tests cover native-only food/activity/workout entrypoints with a persisted legacy marker, startup warning without legacy source reads or writes, historical totals and food chips, blocked rollup and workout-row writes, explicit import, and preserved native display blocks/settings.
- The versioned declared `npm test` suite passed **583 of 584** checks, with zero failures and one optional live provider check skipped. TypeScript and a separate `npm run build` passed. The final build deployed 4.0.0 to Obsidian Plugin Test Vault; Hot Reload loaded the changed plugin.
- Installed Daily logging and Workouts settings showed no line-level storage choice. Logging a synthetic Banana food through the installed dashboard created one `_records/food-entries/*.md` record; the dashboard showed 178 kcal and one food entry both immediately and after Refresh. The synthetic record was moved to `_archive` after QA. The test vault's saved Health settings were not changed.
- Known limitation: inline history does not enter the native dashboard until an explicit copy succeeds. Unresolved import lines require manual review. Physical iPhone behavior has not been tested. Production has not been accessed or installed.
