# TPS Health 0.12.1

## What changed

- Workout mutations can no longer append stale Daily Note set rows outside the active workout block. Live Preview reconciliation is bounded by the matching protected start/end markers and falls back to the vault copy when the editor snapshot has lost that block.
- Repeated start submissions are one-shot, and a second workout is rejected until the active workout is ended. Retrying the same stable workout ID repairs/reuses its existing block rather than adding another heading.
- New and repaired sessions use one clean `## Workout` heading. Legacy titled or missing-boundary blocks are normalized before any exercise, set, template, or completion mutation while unrelated Daily Note content stays in place.
- Set controls use container-aware 6/3/2/1-column reflow, keeping weight, reps, rest, metadata, and actions visible at reasonable sizes in Reading mode, Live Preview, desktop split panes, and mobile layouts.

## Production note repair

- The authorized production repair removed only the malformed workout tail from `2026-08-17.md` and cleared its matching active-workout session state. The unaffected Daily Note prefix was preserved.
- Recoverable pre-repair copies of the Daily Note and Health settings were placed in the production vault's `.trash`.
- Production is still running TPS Health 0.9.0. This release is the BRAT handoff; the plugin runtime was not directly deployed to production.

## Compatibility

- No settings migration or note-property migration is required.
- Existing legacy workout blocks are repaired in place only when their active session is loaded or mutated.
- Minimum supported Obsidian version: 1.12.0.
