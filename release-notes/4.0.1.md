# TPS Health 4.0.1 — Keep ordinary note editing fluid

TPS Health's Live Preview food-log and recipe decorations are registered for every editor. Previously, each keystroke or cursor move rebuilt food decorations across the entire note, and the recipe extension serialized the full note to check for a recipe tag. In ordinary notes, the extensions now inspect only changed or selected lines. Unrelated text edits map existing food chips to their new positions without rebuilding them. Recipe-path notes avoid a full-content recipe search.

Food marker insertion/deletion, chip source-line mapping, recipe tag activation/removal, and ingredient selection keep their existing behavior. No settings, note format, record, or API migration is needed. This is a backward-compatible **patch** release; minimum Obsidian remains **1.12.0**.

## Validation

- Actual CodeMirror StateField regression with a 4,000-line ordinary note and 40 edits plus 40 cursor moves: food-line inspections fell from 320,000 to 160, and no full-content recipe check ran after opening. Focused cases also cover the Health-specific behavior above. These are harness operation counts, not installed-vault frame timings.
- The versioned declared `npm test` suite passed **589 of 590** checks, with zero failures and one optional live provider check skipped. TypeScript and a separate `npm run build` passed.
- The final stable build deployed Health 4.0.1 to Obsidian Plugin Test Vault. Its runtime `main.js` and `manifest.json` matched the tested artifacts, the installed plugin registry displayed 4.0.1 after refresh and a Health-only toggle, and saved Health `data.json` stayed byte-identical. No provider integration was exercised.
- Known limit: the first opening of a note still builds its decorations once. Direct post-fix typing timings in the installed test vault were not captured because UI automation switched its target to another Obsidian window; no actions were taken there. Physical iPhone behavior and production latency were not measured. No other vault was changed; this release is ready for the user's BRAT pull.
