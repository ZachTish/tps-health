# TPS Health 0.3.4

TPS Health `0.3.4` is a backward-compatible frontmatter reliability patch. Health now uses TPS Global Context Menu's supported `frontmatter.process` API directly for every Health-owned Markdown frontmatter mutation when GCM is available, instead of depending on GCM globally replacing Obsidian's host method.

## Changes

- One small Health-owned helper routes all nine Markdown frontmatter write sites.
- With GCM available, food, exercise, workout-plan, rollup, workout-session, set, task-completion, and workout-finish mutations call `api.frontmatter.process` directly.
- Without GCM, the helper calls native Obsidian `fileManager.processFrontMatter` once so Health remains independently usable.
- A `false` result or thrown error from GCM is returned or propagated unchanged. Health does not replay the same mutation through native Obsidian.
- Frontmatter fields, write ordering, settings, note formats, stored health data, public API, and UI behavior are unchanged.

## Before/after evidence

- Before implementation, the four new focused contract checks all failed: the helper was absent, workout completion bypassed the GCM API, and none of the nine call sites used an explicit route.
- After implementation, all four checks pass.
- Source coverage proves nine Health-owned call sites use the helper and only the helper contains the native host call.
- Behavioral coverage proves GCM-first and native-standalone routing, exactly-once mutation, result propagation, thrown-error propagation, no catch-and-replay fallback, and unchanged workout `status`, `completedDate`, and `endedAt` values.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- GCM remains optional. The native standalone route intentionally does not emulate GCM-owned normalization, activity-log, explicit-event, or immediate-index semantics.
- The intentionally credential-gated live USDA check was not run.
