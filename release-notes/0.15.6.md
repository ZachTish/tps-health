# TPS Health 0.15.6

TPS Health 0.15.6 fixes the remaining load-time workout failure. Version 0.15.5 removed the exercise picker's unbounded startup work, but a separate Daily Note repair loop could still run forever when a valid workout block was already the final content in the note. That synchronous no-progress loop pinned Obsidian's renderer and made the vault non-interactable.

## Changes

- Workout boundary cleanup now clamps its candidate index to the shortened note and enters the loop only when that index refers to a real removable line.
- Every cleanup iteration therefore makes progress; an EOF workout can no longer lock the renderer during plugin startup.
- Repair preserves the one linked workout task, one `## Workout` heading, one session marker/end pair, and all unrelated Daily Note content.
- Re-running repair is idempotent.

## Compatibility and migration

- Minimum Obsidian version: 1.12.0.
- No settings migration.
- No Markdown or workout-data migration.
- No public API removal or breaking change.

## Validation

- The production-shaped regression places a complete active workout at absolute EOF with no trailing newline and verifies prompt, idempotent repair plus earlier-task preservation.
- Full declared test suite passes: 183 passed, 1 credential-gated live USDA test skipped, 0 failed.
- A separate production-mode build and byte-for-byte isolated test-vault deployment pass. Runtime reload and production verification are completed before publication.
- The final released artifacts are deployed directly to production only under the user's explicit emergency authorization, and production-owned `data.json` remains untouched.
