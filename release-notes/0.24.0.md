# TPS Health 0.24.0

## Readable native food and workout filenames

- New native food logs use `YYYY-MM-DD - Food title.md` instead of exposing the stable record ID as the filename.
- New workout sessions use `YYYY-MM-DD - Workout title.md`; the generated title's matching ISO date is removed from the title portion so it is not repeated.
- Performed-exercise records inherit the owning workout date and use `YYYY-MM-DD - Exercise title.md`.
- Stable TPS identity remains independent of the physical path. GCM owns filename sanitization, vault placement, backlink-safe renames, and deterministic `(2)` collision suffixes.
- **Native records: Apply readable Health filenames** explicitly upgrades existing opaque filenames. Only files whose basename exactly equals their stable ID are renamed; manual/custom names remain untouched. The operation is idempotent.
- Copy-only legacy import uses the same names without editing or deleting the source note. Reusable food and exercise definitions retain their existing title-only filenames.

This is a backward-compatible minor release because it adds a user-invoked migration command. Existing files are not renamed on load, older GCM versions retain ID filenames, Legacy storage is unchanged, and minimum Obsidian remains 1.12.0. Readable creation and migration require TPS Global Context Menu 1.43.1 or newer.
