# TPS Health 0.10.0

## Intent

TPS Health 0.10.0 hardens the Daily Note workout boundary, publishes an explicit property catalog for TPS Global Context Menu, and makes photographed Nutrition Facts the primary recovery path when a scanned barcode is unknown.

## User-visible changes

- Active Daily Note workouts now have a protected start marker and explicit end marker. Workout rows are inserted only inside that bounded block, so ordinary tasks, prose, Scheduled content, and later sections cannot be consumed or moved as workout rows.
- Legacy active 0.9.0 workout blocks are repaired once on reload: TPS Health recovers only real workout-set rows, adds the end boundary, and relocates the bounded block to the configured placement while preserving unrelated note lines.
- Live Preview replaces whole workout-set source lines with compact controls matching Reading mode. The workout card uses a clean `## Workout` heading, keeps the session title and progress in the card, and uses a mobile-first two-column set layout with accessible 44 px coarse-pointer actions.
- `api.getPropertyCatalog()` returns Health-owned reusable-food property definitions scoped to the current tag/folder/frontmatter identification mode, plus only the configured supported Daily Note food-rollup keys.
- Rollup catalog entries require Health's `healthUpdatedAt` marker and their own populated property. Activity goals are not advertised as food rollups because the food rollup writer does not calculate them.
- A confirmed barcode miss now opens **Scan Nutrition Facts**. The phone captures a rear-camera label photo, prepares a bounded JPEG on-device, and sends it to the device's configured Gemini provider through TPS AI Gateway.
- Gemini returns one strict labeled-serving record for editable review. Printed calories are preserved independently from rounded macro math, and no food is created or logged until the user verifies the name, serving, calories, and nutrients. **Create manually** remains available beside the scan action.
- Label images never enter the synced Controller queue. A device without local Gemini fails with a configuration/manual-entry message rather than writing the photo into the vault.

## Migration and compatibility

- This is a backward-compatible minor release. Existing notes, settings, API methods, food logs, and workout records remain readable; no vault-wide rewrite runs.
- Nutrition Facts scanning requires TPS AI Gateway 0.3.0 with a Gemini secret configured on the device taking the photo. Describe also benefits from Gateway 0.3.0's device-local cloud routing but retains its deterministic fallback.
- The new catalog is read-only and opt-in. GCM changes nothing until the user presses **Import / refresh** in GCM settings, and catalog snapshots must be refreshed after Health identification settings or rollup goals change.
- Minimum supported Obsidian remains 1.12.0.

## Validation

- 163 of 164 declared Health checks passed; only the credential-gated live USDA integration check was skipped. The required separate build was byte-stable and deployed only to the isolated test runtime.
- Obsidian 1.13.7 reloaded the test vault. A deterministic transient barcode miss rendered the Nutrition Facts capture/review entry point without creating/logging a food or sending a photo; the existing tray was restored and the transient override removed. The isolated vault has no Gemini secret, so the live Gemini call remains for normal on-device acceptance after BRAT installation.
- The live USDA provider check remains credential-gated and is intentionally skipped when `USDA_FDC_TEST_API_KEY` is unavailable.
- Production is not accessed or promoted; this release is intended for the user's BRAT pull after publication.

## Known limitations

- Source mode exposes raw workout markers for deliberate recovery; Live Preview protects them and Reading mode hides them.
- GCM receives a snapshot rather than a live subscription, so its explicit import must be rerun after Health scope or goal changes.
- Nutrition Facts extraction depends on label legibility. One close, well-lit full-panel photo is recommended; product name, brand, or ingredients may still require manual entry when they are not visible in that photo.
