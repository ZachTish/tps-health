# TPS Health 5.1.1 — Keep workout controls mounted

Changing set values and adding sets no longer clear and rebuild the whole workout surface. Existing editable rows, inputs and completion buttons stay mounted. New sets append their rows, deleted sets are removed, and reordered sets follow the saved order. Event handlers retain current exercise/set models so repeated completion toggles and menus use fresh data.

Unfinished drafts and rest timing retain their existing protection. Switching workouts, editability, plugin instance or session-action placement can rebuild the surface; changed exercise presentation and set grouping rebuild only affected cards/rows. No scroll-restoration timer, polling, vault cache, settings migration or additional writer was introduced.

This is a backward-compatible patch. Minimum Obsidian: 1.12.0. Existing GCM native-record requirements remain unchanged.

Validation:

- 52 focused renderer tests passed, including 100 saved updates and an appended set with zero root clears and unchanged focused-input identity.
- The retained-input regression fails against released 5.1.0, demonstrating the original replacement behavior.

- Separate production build deployed to the test vault and a targeted Health reload loaded 5.1.1.
- Installed-renderer browser probe: 100 synthetic sets, scrollTop 2500 before/after value update and set append, same focused input, zero full-surface clears. This isolated probe supplied snapshots and temporarily mocked eligibility for its synthetic session; no real workout was saved. It does not prove end-to-end iPhone keyboard behavior.

Physical iPhone acceptance remains outstanding. This release removes the demonstrated full-rebuild behavior; confirmation that it resolves every phone scroll jump requires device testing. Ready for the user's BRAT pull; not directly installed in production.
