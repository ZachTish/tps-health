# TPS Health 3.9.3 — Keep saved Macros visible after mobile reload

Health's startup record index could discard a saved food entry when Obsidian exposed its file before its metadata cache. A later metadata-resolution event might still arrive before that particular cache was ready. Health now keeps the exact unresolved paths pending and indexes each entry when its cache actually becomes available, without enumerating the vault again. A GCM provider rebuild also retains previously accepted entries while their cache is temporarily unavailable. Genuine deletion or removal of record identity still removes an entry. Workout body hydration is scoped to ready sessions, so unrelated pending metadata does not block it.

This is a backward-compatible patch with no note or settings migration, automatic repair, writer, watcher, or polling loop. Minimum Obsidian remains **1.12.0**. Vaults on 3.8.8 also need the earlier 3.9.0 and 3.9.2 startup/metadata fixes included in this release.

## Validation

- The focused native-record suite passed 115 checks, including staggered cache readiness, provider rebuilds, same-path file replacement, stale metadata events, actual deletion, food-definition invalidation, workout hydration, and operation counts. With 256 permanently unavailable caches across 50 `resolved` events, the test observed one vault enumeration, 13,056 cache lookups, and zero body reads, writes, or record notifications. Pending-path checks remain proportional to unresolved files.
- The versioned declared suite passed 589 checks with one optional live USDA check skipped. TypeScript and a separate production build passed.
- The final build installed Health 3.9.3 in Obsidian Plugin Test Vault. After force reloading that test window, the installed plugin's Reading-mode Macros block showed a pre-existing synthetic food record: 1 entry, 210 kcal, 12 g protein, 27 g carbs, and 6 g fat. This was checked in the live DOM; the desktop screenshot capture returned a stale frame.

Physical iPhone behavior and the exact affected-vault startup sequence have not been verified. A literally empty block with no Macros heading is a separate renderer symptom that this index change has not been demonstrated to fix. Production installation remains the user's BRAT pull.
