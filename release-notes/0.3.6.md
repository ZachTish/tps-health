# TPS Health 0.3.6

TPS Health `0.3.6` is a backward-compatible performance patch for saved custom-food search. It preserves the released search contract while calculating each matched food's deterministic relevance score once instead of repeatedly inside the sort comparator.

## Changes

- Macro and query filters still run first.
- Empty and singleton result sets retain the released no-score path.
- Searches with two or more matches decorate each original `FoodItem` with one invocation-local score, perform the same stable descending sort, and unwrap the original objects.
- The runtime adds no cache, timer, listener, fallback, monkeypatch, compatibility shim, persisted state, or unsupported Obsidian API use.

## Preserved behavior

- Search-field construction, normalization, macro eligibility, relevance matching, diagnostics counters, logging, stable tie order, result identities, and downstream usage-aware ranking are unchanged.
- Brand, alias, barcode, serving, nutrition, source, and provider data are unchanged.
- Existing commands, settings, public API, note formats, stored health data, network behavior, and minimum Obsidian compatibility are unchanged.
- No migration is required.

## Before/after evidence

- The permanent operation gate was added before the source change. Exact public `0.3.5` returned the expected eight-food result but failed after evaluating those eight scores 30 times; `0.3.6` evaluates them exactly eight times.
- Throwing accessors prove macro-less and query-miss foods are filtered before scoring. A singleton still performs zero score calculations, while a differently scored two-item result still reorders correctly.
- The released and optimized actual plugin classes produced zero output, order, identity, or supported-error mismatches across 200 representative randomized cases. Score calls fell from 37,518 to 5,089.
- In a controlled 12,000-food benchmark over 21 alternating rounds, score calls fell from 152,098 to 12,000 (92.11%), median search time from 629.091 ms to 71.740 ms (88.60%), and p95 from 643.444 ms to 85.973 ms (86.64%). Output order was identical in every round.
- The production bundle changed from 901,649 to 901,718 bytes, an increase of 69 bytes (0.008%) in exchange for eliminating comparator-time score recomputation.

## Validation

- The final versioned suite passed 126 checks; the one intentionally credential-gated live USDA integration check was skipped.
- TypeScript validation and the mandatory separate production-mode build passed.
- The source artifacts and deployed test-runtime artifacts were byte-identical.
- Obsidian 1.12.7 was reloaded in the isolated Obsidian Plugin Test Vault, where all nine released Health commands remained registered.
- No Health command, modal, provider, setting, note mutation, or outbound automation was invoked during UI verification.
- Test-runtime `data.json` remained SHA-256 `17bd273fc88c814d0d17336acafe9f813de58e6e4a897394ad6849c57f0a0fc0`.
- Production was not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- This does not change the search's `O(N + M log M)` complexity or introduce cross-invocation caching. It removes repeated score work within the existing stable sort for `M` matched foods.
- Objects outside the plugin's supported `FoodItem` contract, such as stateful proxy/getter objects, are not a compatibility target.
