# TPS Health 0.35.0

TPS Health 0.35.0 replaces hardcoded workout timing fields with one configurable Calendar mapping while keeping workout frontmatter lean.

## What changed

- Added **Workouts → Calendar properties** settings for the workout start key, interval style, and interval key.
- New/default sessions use `scheduled` plus numeric `timeEstimate`, matching the normal TPS Calendar Base start-and-duration contract.
- Duration mode stores minutes. End mode stores an ending datetime under the selected key.
- Native workout writes keep only the selected start and interval keys instead of duplicating `startedAt`, `endedAt`, `completedDate`, `durationMinutes`, `durationSeconds`, and `timeEstimate`.
- Existing standard timing aliases remain readable and migrate to the configured pair on the next normal workout mutation. Upgrade does not bulk-rewrite untouched notes.
- Reserved Health/session keys and duplicate start/interval keys are rejected to prevent property-name collisions.
- Workout snapshots, activity totals, readable filenames, legacy import, the public schema, and the GCM Health property catalog now use the same mapping. Refresh the Health import in GCM after changing the keys so Bases receives the selected property names and types.

## Compatibility and migration

- Backward-compatible minor release; settings schema advances to 5.
- Existing workout `session` graphs, reusable exercise definitions, workout controls, and Legacy Daily Note blocks remain compatible.
- Minimum supported Obsidian version remains 1.12.0.
- Production is not modified by this release. It is tested in the isolated plugin test vault and is intended for a manual BRAT pull after acceptance.

## Validation

- Focused native-record integration covers Calendar defaults, custom start/end keys, exact duration projection, legacy alias cleanup, snapshots, and Daily Activity totals.
- Property-catalog coverage verifies custom keys, scope, and datetime/number types.
- Settings coverage verifies normalization, collision protection, schema migration, and the routed settings controls.
- The final declared suite passed 275 checks; the credential-gated live USDA integration was the only skip. A separate production build was byte-identical to the isolated test runtime.
- Obsidian 1.13.7 loaded the new settings. Custom keys and ending-datetime mode persisted, the reserved `status` key was rejected, and the original `scheduled` / duration / `timeEstimate` values were restored without creating workout/note data.
