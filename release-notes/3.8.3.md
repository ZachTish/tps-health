# TPS Health 3.8.3

Health was classifying every file event for food-search invalidation, including non-Markdown assets and source files. Startup also repeated those checks when the catalog and history snapshots were already dirty. This patch checks the actual Markdown path and uses the existing dirty state to skip work that cannot invalidate anything further.

- Renaming a Markdown note to another extension still invalidates its old membership; renaming into Markdown still reaches the existing path checks.
- An in-flight history build still receives generation invalidation and cannot publish a stale snapshot. Clean catalog/history caches keep their scoped invalidation and rebuild on the next query.
- Relevant Markdown events retain exercise-search invalidation. No new cache, watcher, timer, retry, repair, settings/schema/API change or migration.

Patch release; minimum Obsidian **1.12.0**, unchanged. Tested in **Obsidian Plugin Test Vault**, ready for the user's BRAT pull. Not installed or accepted in production.

## Validation

540 declared tests passed, none failed, one optional live USDA test skipped without its credential. Four new actual-plugin regressions cover startup operation counts, repeated invalidation, non-Markdown events and extension-renames; three failed before the fix. Existing real-query cache-reuse and in-flight snapshot protection tests also pass. TypeScript, full-suite build, separate final production-mode build and Test deployment passed. A named disable/loadManifest/enable loaded 3.8.3 with unchanged data.json; the final documentation build matched the already-tested artifacts byte-for-byte and reported the Test runtime unchanged.

Combined-suite foreground warm renderer reloads (desktop, both sidebars enabled, enlarged Test window, all consumers retained):

| Observation | 3.8.2 | 3.8.3 |
| --- | --- | --- |
| Food invalidation calls | 37,301–37,302 | 10,697–10,698 |
| Invalidation inclusive time | 264–289 ms | 1.5–1.9 ms |
| Food path classifications after fix | — | 0 |
| Whole-suite metadata inspections | about 328k | about 254k |
| First visible body, two frames | 2.81 s unprofiled; 2.93 s profiled | 2.60–2.61 s |

Counts are aggregate startup observations, not single-action or independent I/O totals. Timings include instrumentation and persisted/OS caches; the profiled baseline has extra overhead and is not the matching timing comparison. These samples demonstrate less work and a modest warm-start improvement, not an 80% native-performance result or a cold-process/mobile/production guarantee. Other startup/read costs remain.

Installed local-search API verification used real Vault/metadata events with a synthetic food: initial 120 calories appeared, repeat reused the same snapshot, an edit returned 180 calories, and a rename returned the new path. First/repeat/edit/rename searches took 33/0.5/25/41 ms in one instrumented sequence. No provider or UI search action was invoked. Source bytes and settings were preserved; fixtures archived directly, all hooks/debugger removed, previous empty leaf/search/window geometry restored. Eight monitored plugin settings/artifacts stayed unchanged during each startup capture.

## Known limitations

The separate report of missing workout exercise/set controls remains under investigation; this patch does not address it. Existing-record first-edit global identity verification and GCM's late property-panel layout shift are unchanged. No production vault or credentials were accessed.
