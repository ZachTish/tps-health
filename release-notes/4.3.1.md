# TPS Health 4.3.1

Rest timing now belongs to the completed set. Count up tracks the time until another set is completed anywhere in the workout, then freezes that row and starts the newest completion. This patch fixes the ignored existing mode and predictive pending-row ownership; minimum Obsidian remains **1.12.0**.

## Behavior and ownership

Saved completion timestamps define chronological rest intervals across exercises, supersets, drops and reordered rows. Equal timestamps use stable set IDs. Pending rows have no live clock. Reload reconstructs history from the note. A finished workout caps its last interval at the saved actual end; without a valid end it leaves that final interval blank. Existing configurable countdown uses the planned rest target on the same completed row. Rest targets and explicit historical input remain intact; logging no longer replaces targets with the preceding gap or invents a rest-start field.

The existing serialized writer saves the selected completion only. No predictive next-row writer, new stored field, repair, watcher, notification or migration is added. One live interval per displayed ongoing workout updates text only; none runs for terminal/no-completion surfaces. Timing handoffs happen before deferring an unrelated unsaved edit, preserving its input and focus. Editor and Reading share this renderer, including ongoing read-only/unresumed displays.

## Regression validation

Released 4.3.0 reproduced the defect in actual native Complete actions despite configured count-up: the completed row stayed blank while the guessed pending row counted down. Renderer baseline replay passed 24 checks and failed 23 targeted cases; service baseline passed one control and failed four completion cases. The actual bundled main logging route passed seven controls and failed three target/rest-start cases. A saved-target regression additionally caught pristine countdown input using an obsolete target while a separate dirty draft deferred rendering.

Focused tests cover both configured modes, chronology across exercise order/supersets/drops, ties, invalid dates, undo/recompletion, finished/unknown-end history, read-only ongoing rendering, draft timing handoff, countdown targets and disposal. Actual service regressions preserve custom kind/status/session mappings, neighboring data, IDs/order/body and reload/undo/redo. Completion uses one atomic attempt, two scoped source reads and zero inventories; 200 read-only projections perform no reads, inventories or mutation attempts. A 100-tick renderer burst performs no snapshot queries, vault IO or full DOM rebuilds; 100 unchanged/deferred snapshots add no intervals. Main logging preserves explicit positive/zero and configured targets plus authored rest metadata, with unchanged pointer/save/refresh ownership.

## Installed verification and limits

The verified foreground **Obsidian Plugin Test Vault** kept all eight active TPS consumers enabled. Synthetic fixtures used the installed GCM encoder/storage profile and Health field mappings. TEST's existing count-up preference was retained. Native Resume → Complete A1 → Complete B1 showed A1 counting up, then frozen at 16 seconds when B1 completed across exercises; B1 continued counting up while pending A2 stayed blank. Saved IDs, numeric values, body and both reusable definition sources remained intact, with no invented neighbor rest-start fields. A Health-only reload reconstructed the same 16-second frozen interval and live newest completion after the existing index/UI settled; an immediate post-enable capture before UI delivery was blank and was not treated as settled display evidence.

Native Finish froze the last row at the actual saved end (1:12 in this fixture). A later capture retained both frozen values and complete status. The installed prototype renderer/native-DOM replay separately showed first completion frozen at 10 seconds, newest completion advancing 10→30 seconds, pending legacy rest blank, and terminal newest completion fixed at 15 seconds. It registered one interval, invoked 20 captured callbacks, cleared it at finish and performed zero raw/cached reads or note-mutation attempts. Controls retained identity. The replay used an isolated receiver for active/action-bar/recovery gates and synchronous captured timer callbacks plus a synthetic clock; it does not establish native scheduling or event-loop latency.

An actual disable uncovered a lifecycle leak: the editor surface detached, but the Reading footer stayed connected and advanced 25→36 seconds while Health was disabled. The final fix explicitly disposes only the unloading instance's surfaces and clocks, including view containers/popouts. The existing service's disposed flag now makes it unavailable to display consumers; late refreshes and queued Reading mounts stop before touching current leaves or mounting content. Existing in-flight persistence is not canceled, and no new lifecycle flag is introduced. Actual unload, service-disposal and queued/late-refresh regressions cover this boundary. The unload-owner baseline fails; 100 disposed refreshes perform zero inspections/scans/renders, and immediate surface disposal also drops a deferred draft snapshot. The final **4.3.1** artifact was rebuilt/deployed to TEST and Health alone reloaded. Native completion again froze the old row across exercises (23 seconds) while the new row advanced. Actual disable removed both captured editor/Reading roots immediately; their 8-second texts remained unchanged in a later observation. Re-enable/index/UI readiness rebuilt the same 23-second frozen interval and advancing newest row from persisted data. Native Finish saved the actual end and froze the final 58-second interval; a later capture stayed unchanged. The final installed renderer replay retained the same one-clock/zero-IO results above.

The final versioned declared suite passed **736 of 737 checks**, zero failures or cancellations, and one existing optional live-USDA credential skip. TypeScript, suite build with deployment suppressed and a separate ordinary build passed; only `main.js` and `manifest.json` changed in the TEST runtime and complete `styles.css` stayed identical. A missing leaf iterator in an older GCM lifecycle test host was updated to represent its empty workspace; production uses the typed `View.containerEl` boundary. No test failures were skipped.

All eight runtime settings files and enabled-plugin bytes were restored exactly. Each of three QA phases restored original pointer fields and leaf, preserved all note/library/body bytes and archived its three owned files directly from Inbox; nine notes total. All probes/globals/owned DOM were removed, and canonical dirty source was untouched. Outbound automation remained disabled. Normal workout creation and live provider calls were not tested in this scoped completion/rest QA.

No outbound providers or production vault were accessed. Physical iPhone/iPad and installed editor interaction timing remain unmeasured; shared editor/Reading consumers have regression coverage. This is functional and operation-count evidence, not a production or mobile speed claim. Production installation remains the user's BRAT pull.
