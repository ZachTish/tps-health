# TPS Health 0.22.0

This backward-compatible feature release publishes Health's complete kind-scoped GCM field catalog and consolidates native Health note identity around `tpsId`.

## Changes

- The Health property catalog advances to version 2 and includes the typed fields Health writes for food, activity, workout session, workout exercise, reusable exercise, and workout-plan notes.
- Each catalog field declares its exact logical record kinds, allowing GCM to show Health fields in stacked Properties only where they apply.
- Shared `name` fields use the neutral **Name** label across reusable food, exercise, and plan notes; the separate `foodName` record field keeps its specific **Food name** label.
- New native food records no longer duplicate `tpsId` as `foodId`.
- New workout sessions no longer duplicate `tpsId` as `workoutId` or store an exercise-ID join list.
- Workout-exercise records use one durable `workout` wikilink and `exerciseOrder`; legacy ID/path joins remain readable.
- **Native records: Consolidate Health identities** converts compatible legacy aliases explicitly and idempotently. Relationship data is established before old joins are removed, while conflicting or unresolved records fail closed.
- Copy-only legacy import writes the version-2 relationship form without changing its source logs.

## Compatibility and known limitations

- Native-record mode remains opt-in. Existing records are not rewritten at load, and Legacy Daily Note/body storage is unchanged.
- Set IDs remain because sets are independently addressable child rows, not duplicate note identities. External `sourceId` values remain provider identities.
- Reusable food, exercise, and workout-plan notes continue to use their real Markdown paths as catalog identity. This release does not bulk-assign `tpsId` to curated library notes.
- GCM 1.40.0 or newer is required to import and apply the version-2 kind-scoped catalog. Minimum Obsidian version: 1.12.0.
