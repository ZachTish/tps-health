# TPS Health 0.15.8

TPS Health 0.15.8 makes Describe fail safely into a complete editable tray instead of dropping foods, creating empty results, or relying on reusable food notes.

## Changes

- Every non-empty top-level described food becomes exactly one tray item even when Gemini and all search/index routes fail.
- Named composite dishes remain one row when ingredient quantities are included. The reported Diet Coke, Honeycrisp apple, and measured ham-and-Velveeta sandwich input produces three rows.
- Fragmented Gemini extraction is rejected when it replaces or expands a locally identified composite dish.
- Saved and provider nutrition can inform an estimate, but every Describe result is converted to `custom-inline`; no reusable food, recipe, or meal file is created.
- A conservative category-aware local estimate is the final fallback. Unknown foods receive editable nonzero nutrition, while credible zero-calorie drinks remain zero.
- Durable Describe stage IDs and the device-local checkpoint version were advanced so older fragmented extraction output is not reused.

## Compatibility and migration

- Minimum Obsidian version: 1.12.0.
- No vault-note migration.
- No settings migration.
- No public API removal or breaking change.
- Incomplete legacy Describe checkpoints are rebuilt; already-prepared pending trays remain in the existing pending-food draft.

## Validation

- The exact reported three-food phrase is covered end to end with deliberately fragmented Gemini extraction.
- A second end-to-end regression forces Gemini, history, local search, and remote search to throw and still receives one non-empty editable inline tray item.
- Both regressions assert that the fake vault file count is unchanged.
- Full declared suite: 187 passed, 1 credential-gated live USDA check skipped, 0 failed.
- A separate final production-mode build deploys byte-identical artifacts only to the isolated test runtime. UI reload was intentionally not attempted because the only open Obsidian window was the production vault; production was identified read-only and left untouched.
