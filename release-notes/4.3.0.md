# TPS Health 4.3.0

Active/resumed whole-note workouts now provide **Remove exercise** in the exercise’s three-dot menu. This compatible capability receives a minor version; minimum Obsidian remains **1.12.0**. Existing settings, defaults and note schema are unchanged.

## Behavior and ownership

Removal deletes the selected exercise and its sets from the workout session. It preserves the workout note/body, reusable exercise definition, active pointer and neighboring identities, order, links and sets. The final exercise can be removed, leaving an empty usable workout. Completed/history workouts retain the existing read-only policy.

The existing serialized session writer owns the mutation. Configured kind and property mappings remain authoritative. Fresh-source and atomic-frontmatter guards reject stale identity/schema/kind, finished or archived sessions; duplicate/missing exercise identities fail closed. Unlinking skips reusable-definition resolution, so it does not recreate missing or archived definition notes. Only rest starts referring to the removed sets and a singleton left in the removed exercise’s superset are cleared; unrelated authored singleton groups are preserved. No new repair, retry, watcher or state store is introduced.

Removed exercise cards disappear before the existing draft deferral. An unsaved edit on another exercise retains its control, value and focus. Rest intervals are allocated only for incomplete sets with a valid rest start. Completed sets and missing/invalid dates allocate none. Elapsed-only refresh keeps controls and timer registrations unchanged.

## Regression validation

Seven initial actual-service removal tests reproduced missing-method failures on 4.2.7. Nineteen service checks now cover operation counts, definition/body preservation, empty/custom-mapped workouts and reload, exact/ambiguous identities, superset/rest relationships, duplicate bursts, concurrent graph edits, atomic failures, queued finish and fresh/atomic identity/status/schema/kind/archive guards. Three actual bundled-plugin menu checks cover routing, active ownership and failure reporting without replay/pointer mutation.

The actual renderer has 29 passing checks, including removal with dirty fields, retained draft focus, rest eligibility, elapsed-only bursts and detach cleanup. The 4.2.7 renderer replay passes 20 and fails the nine targeted regressions. Editor/Reading consumers retain their existing lifecycle coverage.

A valid modern removal makes one atomic frontmatter attempt, two scoped authoritative session reads, zero cached reads, zero inventories, zero definition resolutions/creates, zero note trash and zero body rewrites. Duplicate removal bursts reject the duplicate before a second removal write; a separately requested retained-set change still commits.

## Installed verification and limits

The final versioned declared suite passed **699 of 700 checks**, zero failures or cancellations and one existing optional live-USDA credential skip. TypeScript and the suite build passed with deployment suppressed. A separate ordinary production build deployed only `main.js` and `manifest.json` into **Obsidian Plugin Test Vault** (`target=test`); the complete standard stylesheet remained byte-identical. Health alone was reloaded after refreshing its native manifest, with all eight active TPS consumers enabled.

In the visible foreground TEST window, the actual Reading surface resumed a synthetic workout and opened its native exercise menu. **Remove exercise** removed a two-set exercise, then an empty slot, then the last retained exercise. Current-source checks confirmed preserved neighboring IDs/order/values, dependent-rest and affected-superset cleanup, independent rest, both reusable definition files, workout body and active identity. The final note remained active with zero sets/exercises and the visible **Add first exercise** action; it remained empty after Health reload. Source/editor and Reading consumer regressions cover their shared menu/render owner; physical iPhone/iPad and an installed editor-mode removal were not independently tested.

The actual installed renderer was replayed on attached owned native DOM, using an isolated receiver for active/action-bar/recovery gates and a synchronous captured timer-host boundary. For 25 completed active-session sets, timer registrations changed **25 → 0** and 20 replayed ticks plus detach changed **525 → 0 callbacks**. A mixed case (25 completed + one valid pending rest + one invalid rest date) changed **27 → 1 timers**, **567 → 21 callbacks**. Repeated elapsed-only rendering retained all control identities and registered no extra timers. Both versions performed zero raw/cached reads or note-mutation attempts in this renderer probe, and all owned timers/DOM were removed. This checks the shipped renderer and eligibility, not real timer scheduling, event-loop latency or wall-clock speed.

The final native-menu removal was also measured with real persistence and the enabled consumers: **one frontmatter attempt, seven raw selected-session reads, two cached selected-session reads and zero Markdown inventories** during the service promise. These installed aggregate counts include the actual GCM/native authority and any consumer work within that window; they are separate from the two explicit owner reads in the synthetic service contract and do not encompass later metadata deliveries. The extra authority reads remain a follow-up investigation, not a claim of a fully optimized suite.

QA used three owned Inbox notes created through core persistence with the installed GCM encoder/storage profile and Health field mappings; it did not test normal workout creation. The test vault currently has an empty v2 classification definition list and its existing native API accepts the legacy configured envelope. An initially overstrict reusable-classification assertion rejected fixture preparation before creating notes; correcting only the QA helper enabled the real removal flow. No runtime fallback or configuration change was made. Exact Health active-pointer fields, all eight runtime settings files and the enabled-plugin list were restored byte-identically; three fixtures and the empty owned folders were archived. Original leaf, unrelated dirty canonical source and runtime-owned state were preserved, and all QA globals/wrappers were removed. Outbound automation remained disabled.

These are scoped functional and operation-count results, not physical mobile or production latency measurements. Test-vault acceptance is complete and the release is ready for the user’s separate BRAT pull. No production deployment is included.
