# TPS Health 0.21.0

This backward-compatible feature release makes native-record workouts usable as a persistent, table-shaped mini-app while keeping their Markdown bodies clean.

## Changes

- Native workout-session notes render one compact exercise/set table in Live Preview and Reading View.
- The table exposes `Set`, `Reps`, `Weight`, `RPE`, `Rest`, and `Type`, with workout and exercise totals derived from the incremental native-record index.
- Add exercise, add set, and finish actions reuse Health's existing reviewed mutation flows. No parallel record writer or body block was added.
- Repeated sets preload the last saved values for that exercise as editable defaults. No set is written until the user confirms the form.
- Completed sessions keep their saved table after active state clears. A cold-reload index rebuild prevents transient empty sessions.
- True Source mode remains literal: Health adds no table widget, code block, heading, or template to the source body.

## Compatibility and known limitations

- Native-record storage remains opt-in; Legacy workout blocks retain their existing inline table and controls.
- The persistent table is intentionally read-oriented. Editing or deleting an already-saved set still uses the existing Health workout workflows; this release does not add arbitrary direct frontmatter editing inside the table.
- Extremely narrow desktop panes contain the table horizontally rather than collapsing metrics into ambiguous cards. Normal mobile and desktop note widths show the full static grid.
- No settings, API, or record-schema migration is required. Minimum Obsidian version: 1.12.0.

## Validation

- The final declared suite passed 208 checks: 207 passed, one credential-gated live USDA check was skipped, and zero failed. TypeScript and the mandatory separate production build also passed against the final versioned source.
- Test-vault UI QA created a native workout and a previously unknown exercise, logged two sets (12 × 80 lb and 10 × 90 lb), observed immediate table refresh and exact totals, reopened the exercise-level set form with the prior set prefilled, finished the workout, cold-reloaded the app, and verified the completed table persisted.
- Live Preview, Reading View, true Source mode, a constrained pane, and a full-width note were checked. Source showed only literal YAML/body content; no table or body marker was present.
- The session and exercise bodies stayed empty. QA records were archived, original Health/GCM storage modes were restored, and production was not accessed.
