# TPS Health 0.31.0

This release applies the shared atomic-note model to native Health records.

- `tpsId` is the sole TPS identity. GCM v6 reads and canonicalizes it case-insensitively; Health no longer has an ID generator that could create a second differently-cased key. Standalone reusable-note creation remains usable without GCM but leaves identity absent or unchanged.
- Workout exercises and sets remain part of their one owning workout-session note, stored in a versioned hidden body marker instead of the visible `workoutData` property. A single service-owned per-path queue serializes session changes, compares the exact marker within `Vault.process`, retries sync races, and never replays a successful body mutation merely because GCM cleanup needs retrying. Semantic-update failure rolls back the marker with another compare-and-swap so body and frontmatter cannot commit divergent states.
- Food entries use one normal `food` wikilink plus `quantity` and `unit`; `foodPath` and serving aliases remain read-only compatibility inputs.
- Reusable foods, exercises, and workout plans use `title` as their display name. The compact GCM catalog offers only properties a person may store, edit, filter, or group by.
- Native writes require the exact enabled GCM nativeRecords API v6 and fail closed on older boundaries. Legacy Daily Note/body logging remains compatible.
- Generated and repaired Food Log Bases sort by `completedDate` with `file.mtime` as the fallback. Blank food, recipe, exercise, and workout identity tags remain deliberately blank after normalization and reload.
- Generated workout filenames contain one authoritative Daily Note date even across local/UTC day boundaries: the ISO date is removed from the exact generated `Title YYYY-MM-DD HH.mm` suffix when it matches `startedAt`, while authored date-bearing and timestamp-like titles remain intact.
