# TPS Health 0.9.0

## Intent

TPS Health now treats the Core Daily Note as the clear home for food and live workouts, while reusable foods, recipes, meals, and optional workout files remain linked records. The release also makes generated note identity and recipe ingredients obey the user's selected Obsidian property model.

## User-visible changes

- Daily Note folder and filename format come directly from Obsidian's Core **Daily notes** settings. Health no longer owns duplicate folder/format inputs, and slash-containing formats create required nested folders.
- The optional GCM **Log food** action is registered, shown, and accepted only on an exact Core Daily Note.
- Food identification mode is now a write contract: Tags only writes the configured tag without `kind`; Frontmatter only writes `kind` without the identity tag; Folders only writes neither; the combined mode writes both.
- Recipe and meal ingredients use the YAML `ingredients` list. Body headings, directions, notes, custom wikilink labels, and legacy ingredient compatibility are preserved. The full editor retains Add, Replace, and Remove with guarded nutrition refresh.
- Every workout creates a real `## Workout — …` section in the selected Daily Note. A saved template inserts its exercises and sets; a blank workout stays blank until **+ Exercise** or **+ Set** is used. **End workout** completes the active session from the same card.
- A dedicated workout note is optional. Legacy dedicated-only settings are normalized to dedicated note plus Daily Note so no new workout can silently bypass the daily surface.
- Workout insertion can be placed after properties, above the first real level-2 heading, or at the bottom of the note.
- The hidden workout identifier is rendered as an atomic locked range in Live Preview and is absent from Reading mode. A transaction guard rejects typing, Backspace, Delete, paste, and selection edits that would change the marker or join it to another line. Completion fields stay inside the hidden comment so the finished card remains intact; Source mode remains available for deliberate recovery.
- Food log rows now share one polished two-line card in Live Preview and Reading mode. The wrapping title uses the first row with calories at the end; serving and wrapping macros use the second row.
- Food and workout cards use container-aware narrow layouts and at least 44 px coarse-pointer actions for mobile and small Obsidian panes.

## Migration and compatibility

- The Health settings schema advances to 3. Legacy `dailyNoteFormat`, `dailyNoteFolder`, and retired workout layout keys are removed. `session-note` workout storage becomes `both`; `daily-note` remains daily-only.
- Existing Daily Notes, food log rows, workout session notes, commands, and public API return behavior remain readable and compatible. Starting a workout with an optional dedicated note still returns that note path to existing integrations while the UI opens the Daily Note.
- Existing body-based recipe ingredients remain readable and migrate into the list property only when TPS Health next updates the recipe or meal. There is no vault-wide rewrite.
- Existing identity signals remain readable. Notes are normalized to the selected identity mode only when TPS Health creates or updates them.
- Minimum supported Obsidian remains 1.12.0.

## Validation

- Final versioned `npm test` passed 159 of 160 declared checks: 3 Home actions, 2 food-log date cases, 138 of 139 Health/provider cases, 9 Describe cases, and 7 settings-layout cases. The only skip was the credential-gated live USDA check.
- A separate production-mode build passed, deployed the 0.9.0 artifact to the isolated test runtime, and Hot Reload reloaded TPS Health in Obsidian 1.13.7.
- Test-vault UI verification confirmed the Core Daily Notes handoff and workout placement settings; matching complete food cards in narrow Live Preview and Reading panes; a live Daily Note workout card with mobile-stacked `+ Exercise`, `+ Set`, and `End workout`; Backspace rejection at the locked marker boundary; and a completed disabled card whose metadata remained hidden. Synthetic workout notes were moved to `_archive` after verification.
- The provider suite intentionally skips its credential-gated live USDA check when `USDA_FDC_TEST_API_KEY` is unavailable.
- Production is not accessed or promoted; this release is intended for the user's BRAT pull after publication.

## Known limitations

- Source mode exposes the raw workout marker for deliberate recovery; the atomic protection applies to Live Preview, while Reading mode hides the marker entirely.
- Changing Core Daily Notes settings does not move existing notes or rewrite historical `dailyNotePath` fields.
- Manually editing the native `ingredients` property does not immediately recalculate recipe nutrition. Use the TPS Health editor or its Add/Replace/Remove actions when totals must refresh in the same operation.
- Mobile behavior is implemented with container-aware layout and coarse-pointer contracts; device-specific theme differences may still need follow-up after an iPhone BRAT pull.
