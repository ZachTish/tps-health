# TPS Health 0.26.2

## Compact Health properties

- Native food, activity, and workout-session records now store authored facts instead of duplicating identity, title, date, serving conversions, scheduling aliases, or calculated workout summaries.
- Workout counts, reps, volume, duration, and local date remain derived in memory for the workout UI, Daily dashboard, and public snapshots. Food entries keep core macro numbers for Bases and omit zero-valued optional nutrient properties.
- New default exercise and workout-plan notes no longer persist empty arrays, inherited defaults, fixed workflow boilerplate, duplicate cooldown fields, or blank history. Explicit values and custom-template fields remain supported.
- The GCM import catalog is intentionally smaller: 18 reusable-food fields and 28 unique native/reusable fields, plus the user's configured Daily Note rollups. Use GCM's explicit **Install TPS task and Health fields** action once after updating to remove retired imported Health definitions.

Existing untouched records are not bulk rewritten. Normal food projection refreshes and workout mutations clean redundant fields from only the record they already need to update. Old fields and legacy child records remain readable, so no migration is required. Minimum supported Obsidian remains 1.12.0.
