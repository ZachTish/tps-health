# 11.1.0 — Selected daily-note nutrition totals

Restores daily-note nutrient properties from Health's current indexed food logs and linked food definitions. In **Daily logging → Daily nutrition totals**, select Command only or When food changes and choose the totals to copy. Default is Off. Calories, protein, carbohydrates and fat are preselected; additional tracked food nutrients are offered. Goal values stay in goal notes. No inline-log writer is restored.

Automatic updates consider only dates affected by meaningful indexed nutrition changes. No startup/backfill, navigation writer, timer, poller, additional data cache or vault scan is introduced. The explicit Update current daily nutrition totals command refreshes an existing daily note, including historical days. GCM's current daily-note resolver remains the owner of naming and identity; notes are never created by the rollup. Turning off or deselecting a metric preserves existing saved properties.

Incomplete labels and days without logs remain blank; known zeroes stay zero. Archived logs are excluded. Source-preserving scalar YAML updates retain IDs, unrelated properties/comments and all body bytes. No-op metadata preflight avoids reads/queues. The existing Vault.process boundary rechecks index readiness, selected settings, exclusions, target identity, source bytes and open editors. Unsaved/concurrent changes fail without a retry loop. GCM's asynchronous file exclusion guard is awaited; its configuration and synchronous source guard are checked again at commit.

Settings stay within the existing five-destination hub. The one Totals to copy disclosure and native controls use existing mobile layout/accessibility behavior. Built-in settings search includes the new controls. Existing settings keys, commands and goal authority remain unchanged; the only new preference is dailyNutritionRollup (mode and selected nutrient keys). Removing this preference restores Off. Minimum Obsidian remains 1.12.0.

## Validation

- Full declared suite: 916 tests, 915 passed, 0 failed, 1 skipped (optional live USDA credential check). Separate final build passed. Settings search: 124 entries across five destinations.
- Final 11.1.0 bundle deployed and reloaded in Obsidian Plugin Test Vault, with Sync disabled and normal consumers enabled. Inspected all five settings destinations, all three update modes, nutrient selection/removal/restoration and the native Update totals button. Existing mobile CSS and its regression coverage passed; no physical iPhone/iPad acceptance is claimed.
- Real indexed food-log portions, linked-food label edits, date moves, missing nutrients and archived logs updated the correct existing daily notes. Comments, unrelated properties, body text and CRLF were retained byte-for-byte. Source/editor/exclusion/configuration conflicts and missing/ambiguous daily targets are covered by focused regressions.
- 100 unchanged metadata/body events queued no daily updates. A broad initial counter also saw two cached reads from the two enabled Notebook Navigator plugins; stack traces and an Off-mode control attributed those reads to those consumers. The automatic-mode repeat used zero reads, scans or processes. Another 100 unchanged explicit commands used zero reads, scans or processes (57 ms total).
- Six installed writes measured 6–16.3 ms. Document visibility was visible but focus was false during these CLI-driven samples; these measure the write path, not foreground interaction latency or phone speed. One 57 ms long task occurred during the overall instrumented session and is not attributed to the rollup.
- Synthetic fixtures archived after QA. Temporary in-memory preferences and instrumentation removed. Health data/private marker and the enabled-plugin list were byte-identical to their original hashes; final reload restored Off with the four default nutrients. No production access or deployment occurred for this release.

Tested in the test vault and ready for the user's BRAT pull. Production installation and user acceptance remain separate.
