# TPS Health 3.8.4

Fixes workout controls missing from an open Live Preview note when Health discovers its session after the editor has already opened. Previously the existing index refresh updated mounted controls but never created the missing CodeMirror decoration. A cursor movement happened to create it. The editor also selected its workout from the globally active file, which could belong to another tab or pane.

The existing refresh now updates native decoration membership through a CodeMirror state effect, using Obsidian's public editorInfoField for the owning file. Already-indexed sessions do not depend on a separate metadata cache catching up. Membership is compared against decorations, not visible DOM, so virtualized/offscreen widgets and unchanged refreshes do not dispatch repeatedly. No new observer, timer, scan, cache, note writer, repair, retry, settings migration or separate set page. Existing Reading mode, session storage, exercise/set mutations and APIs are unchanged. Backward-compatible patch; minimum Obsidian **1.12.0**.

## Validation

- Five actual CodeMirror EditorState/StateField regression tests cover another active file, delayed discovery, classification removal, metadata lag, ordinary files, literal Source mode and 100 unchanged refreshes. Three initial regressions failed against the previous implementation. Existing native workout surface tests also pass.
- Full declared versioned suite: **545 passed, zero failed, one optional live USDA test skipped** without its credential. TypeScript passed. Separate production build deployed main.js/manifest.json to **Obsidian Plugin Test Vault**, and named Health reload verified **3.8.4**.
- Installed baseline on 3.8.3: a fixture-scoped isWorkoutSession predicate withheld recognition while a real Live Preview editor opened. After restoring the real settled index, the existing refresh still left zero controls; a selection-only editor transaction immediately produced one surface. No note edit was needed to demonstrate the missing refresh.
- Installed 3.8.4: the same first and repeated operation produced one surface after index readiness, without moving the cursor or editing the note. The first capture recorded **one editor dispatch, zero raw reads, cached reads, Markdown enumerations, modifies or process calls**; 100 unchanged refreshes added **zero** dispatches or those operations. The first sample was visible/unfocused; the repeat and actual UI actions were visible/focused. These are operation counts, not production timing claims.
- Real recovered controls were clicked: Resume, Add Exercise, and Add Set persisted one reusable exercise link and one inline set in the same session. Focusing another tab and dispatching an editor selection transaction kept the workout controls bound to their own note without changing editor text. Finish cleared active state. No GCM timer setting or outbound automation was enabled.
- Health settings SHA-256 matched before/after. Synthetic Inbox fixtures were archived, probe hooks removed and original leaf restored. Other installed consumers remained enabled. The final documentation-only rebuild was checked byte-for-byte against the tested runtime.

The reproduced missing-controls defect is fixed. The user's earlier report of tapping without an addition could not be independently reproduced: the tested additions saved successfully. The exact affected note's frontmatter is still requested to distinguish any separate identity/session issue. Physical iPhone/iPad startup and that specific existing workout remain unverified.
