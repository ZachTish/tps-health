# TPS Health 3.8.1

Health's Reading-mode food and workout postprocessors now check for relevant rendered elements before reading the note body. Plain paragraph sections no longer start two concurrent full-note cached reads, and already-rendered workout headers no longer reread their source.

The recipe route retains the empty-recipe **+ Ingredient** control. Source-backed hidden food fields, custom units, menus and workout marker mapping are preserved, along with the existing concurrent-header check after reading. Sections with list items or unprocessed level-two headings retain their source reads; recipe identity checks and other renderers are unchanged. No new cache, watcher, retry, maintenance writer, settings/schema/API change or migration. Backward-compatible patch; minimum Obsidian **1.12.0**.

## Validation

- **530 tests passed, zero failed, one optional live USDA check skipped** without its credential. TypeScript, the versioned suite build and mandatory separate final build passed under Node **24.19.0**. Eleven actual-function/class regressions include the two previously failing operation-count checks: 700 ordinary paragraph mounts performed 1,400 cached reads, and twenty processed-header refreshes performed twenty; both now perform zero. Eligible food/recipe/workout behavior, concurrent headers and errors remain covered.
- The final artifact was deployed only to **Obsidian Plugin Test Vault** and verified through a named Health plugin reload. The separate final normal build after documentation is byte-identical to the installed artifact. Runtime-owned files/settings were preserved.
- Paired visible, focused Reading-mode captures used the same **C, A, C, A, C, A** clicks: C is a 700-paragraph note, A a short ordinary note. Across the three C opens, cached reads fell **4,209 → 3**, raw reads **4,215 → 9**. Across both fixtures, cached reads fell **4,284 → 6**. Whole-window raw reads fell **4,368 → 162**; both 30-second windows include the same 147 unrelated background reads, so those remaining calls are not attributed to this fix.
- C's three observed pointer-to-visible-body times were **85.1 / 65.5 / 67.5 ms** before and **64.5 / 51.1 / 50.4 ms** after. Six clicks per version are a bounded check, not proof of native-equivalent responsiveness, cold-start improvement, physical-device behavior or production speed. Both captures retained correct final content and stable artifacts/settings, with no recorded mutations, errors or long tasks. Temporary listeners were removed and the original view/search restored.
- Installed visual/accessibility checks confirmed the synthetic hidden-source **QA Apple** chip (190 kcal, two servings and macros), completed **QA Press** workout header, and **+ Ingredient** for an empty recipe. Fixture bytes and settings stayed unchanged; owned fixtures were archived. The existing recipe control may appear in more than one rendered section; this patch preserves that behavior. A smoke-report selector used the wrong food-chip class and counted zero, so food presence was verified through visible/accessibility content rather than that selector.

Tested in the isolated test vault and ready for the user's **BRAT pull**. Production, provider services and outbound automation were not accessed. Device acceptance remains separate.
