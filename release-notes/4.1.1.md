# TPS Health 4.1.1 — Daily Note context follows GCM mappings

A Daily Note whose location or filename does not match Core Daily Notes configuration now supplies the correct day to Health's Macros and Activity blocks when it has GCM's configured `dailynote` classification and Scheduled custom-property key. This includes nested kind lists and a renamed date key. A stale legacy date or an unrelated kind cannot take precedence. Earlier GCM installations keep the scalar `kind: dailynote` and `date`/`scheduled` reader.

GCM remains the settings owner. Health adds no new persisted setting or note rewrite. This is a backward-compatible **patch** release; minimum Obsidian remains **1.12.0**. Configure GCM's Daily Note kind and Scheduled property before the coordinated TishOS v0.2 migration.
