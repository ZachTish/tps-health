# TPS Health 0.19.2

This patch replaces the product-specific White Claw workaround from 0.19.1 with generalized provider-search handling.

## Changes

- Removed the curated White Claw Surge record and its special known-brand entry.
- Open Food Facts rows can now combine `product_name` and `generic_name` when the user's multi-word query genuinely spans both fields. This handles future split-identity records without knowing the brand in advance.
- Missing provider brand metadata stays missing instead of being guessed from a hardcoded list; the complete searchable identity is retained in the result name and aliases.
- Alcohol-bearing products no longer fail the nutrition guard solely because protein, carbohydrate, and fat are all zero.
- The provider query remains unfielded so records that omit `brands` can match through full-text identity fields. Open Food Facts documents `product_name` and `generic_name` as separate identity fields and unfielded Search-a-licious words as full-text terms: https://openfoodfacts.github.io/documentation/docs/Product-Opener/schemas/schemas/product/ and https://openfoodfacts.github.io/search-a-licious/users/explain-query-language/

## Compatibility and validation

- Backward compatible; no settings, storage, or API migration.
- Minimum Obsidian version: 1.12.0.
- Generalized coverage uses an unknown fictional brand, reversed query order, split provider identity, alcohol-only macro data, final ranking, and an explicit no-curated-fallback assertion.

- Final versioned suite: 203 checks; 202 passed, one credential-gated live USDA check skipped, zero failures.
- TypeScript and the mandatory separate production build passed. The byte-identical artifacts were deployed to the isolated test vault, whose existing Hot Reload marker provides the reload path. Production was not accessed.
