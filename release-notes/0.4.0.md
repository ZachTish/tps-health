# TPS Health 0.4.0

TPS Health 0.4.0 makes barcode capture faster and much less sensitive to label angle or camera distance, and replaces raw-looking mobile Live Preview food-log lines with compact editor-width chips.

## User-visible changes

- The live scanner requests a sharper rear-camera stream, enables ZXing `TRY_HARDER`, starts supported native detection immediately, and continuously cycles bounded full-frame and enlarged-center correction passes for arbitrary barcode orientation.
- Supported cameras use continuous focus, a centered point of interest, and a short adaptive optical-zoom pass after an initial close-range view. Each optional camera constraint is isolated so unsupported hardware falls back cleanly.
- ZXing Browser 0.2.1 and ZXing Library 0.23.0 improve current browser integration and ordinary 1D row coverage.
- On Obsidian Mobile, completed food-log lines in Live Preview become compact block chips whenever the cursor is elsewhere. Selecting a line reveals its original Markdown for editing. Long food names and macro pills wrap inside the editor instead of producing an oversized line.

## Compatibility and migration

- Minimum supported Obsidian version: 1.12.0.
- No settings, note-data, or API migration is required.
- The native iOS VisionKit scanner still depends on a bridge supplied by the host app. When none is available, the improved web-camera path is used.

## Validation

- The declared suite passed 128 runnable checks; the one credential-gated live USDA request was skipped.
- Focused regressions cover arbitrary-angle correction with a maximum 11.25° residual, close/distant zoom planning, camera constraint requests, concurrent scanner paths, mobile block decoration, width containment, and wrapping.
- The mandatory standalone build deployed only to the isolated test vault. Obsidian 1.13.7 was reloaded, the scanner command and camera-first surface were verified, and synthetic long food-log records were inspected in Live Preview without logging food or calling a provider.
- Runtime-owned `data.json` and `.hotreload` remained unchanged. Production was not accessed.
- Desktop camera playback was unavailable in the QA environment, so physical iPhone camera speed and final on-device appearance remain the acceptance checks after installation through BRAT.
