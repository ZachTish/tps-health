# TPS Health 0.15.1

TPS Health 0.15.1 replaces the still-bulky workout set cards with the compact table requested from the supplied visual reference.

## What changed

- Each exercise shows its name and one shared `Set / Weight / Reps / Rest / Done` header.
- Every set remains one short table row at ordinary, split-pane, and phone widths; it no longer becomes a two-row or one-card-per-metric layout at 520 px.
- Weight, reps, and rest remain directly editable. Keyboard arrows still adjust them, while the prior-set copy action, units, set type, copy, group linking, and deletion remain in the row menu.
- Completion is a small square action and `+ Set` is a short footer row.
- The workout summary uses compact `+ Ex / + Set / End / Discard` controls and stays inline until the container is truly narrow.
- Superset metadata no longer paints a colored left rail.

## Compatibility

- Minimum Obsidian version: 1.12.0.
- No settings, API, note-schema, or Markdown migration is required.
- Existing workout records and live sessions render in the new layout without being rewritten.

## Validation

- 180 of 181 declared checks passed; only the credential-gated live USDA check skipped.
- Focused regressions require the shared table header, five persistent set columns through 330 px, compact header actions, hidden per-set labels/previous-result cards, a small completion control, and the absence of stacked metric grids or colored left rails.
- The production-mode build deployed to the isolated test runtime, the mandatory separate build was byte-stable, source/runtime artifacts match, and plugin-owned `data.json` was unchanged.
- Visual automation was intentionally stopped when the only focused Obsidian window proved to be production; production was not clicked or changed.
