# TPS Health 0.3.1

TPS Health `0.3.1` is a backward-compatible indexing and rollup efficiency release. It removes unrelated files from local-food timestamp sorting and eliminates a duplicate daily-note read without changing food discovery, ordering, nutrition totals, fallbacks, providers, settings, or stored health data.

## Changes

- Local food indexing obtains metadata for the Markdown snapshot, filters eligible food/recipe notes, and then sorts only those candidates by the same timestamp comparator.
- Scan accounting still reports every inspected Markdown file, and stable ties retain the original vault order.
- Daily rollup updates pass their already-read daily-note content into rollup source resolution.
- Daily-note, single-file log, and missing-log fallback routes now read the daily note once while retaining the same totals and fallback behavior.

## Performance evidence

- The focused catalog test uses 200 unrelated Markdown files plus four food notes and proves only the four eligible candidates participate in timestamp sorting.
- The focused rollup test proves one daily-note read for each supported storage route, including the missing single-file fallback.
- Local food discovery must still inspect cached metadata for every Markdown file to determine eligibility; this release intentionally avoids adding a new invalidation catalog or persistent cache.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- Provider credentials, network routing, food identification modes, rollup formulas, and all existing UI flows are unchanged.
- The initial food-candidate determination remains an `O(N)` metadata inspection; this release optimizes the subsequent sort without adding cache invalidation complexity.
