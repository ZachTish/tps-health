# TPS Health 0.24.1

## Active workout continuity after readable filename migration

- The explicit readable-filename migration now captures the active workout identity before any rename.
- After the batch, Health resolves the active session from both the rename result and its stable-ID native record index, then atomically persists the exact ID/path pair before reporting completion.
- A persistence-time compare-and-set guard checks the latest stored ID/path pair inside Health's save queue. It prevents the migration from resurrecting an old session—or combining two sessions—if the workout is finished, discarded, replaced, or changed by sync while filenames are being normalized.
- This repairs the case found during 0.24.0 POC rollout where all eight files were renamed correctly but `activeWorkoutPath` still referenced the removed opaque filename.
- Existing readable files, record identity, manual filenames, workout data, food data, and Legacy storage are unchanged.

This is a backward-compatible patch release. Minimum supported Obsidian remains 1.12.0 and readable filenames still require TPS Global Context Menu 1.43.1 or newer.
