# TPS Health 11.0.0 — Calculated food logs

Food logs now store the linked food, consumed amount/unit, date and ordinary identity/user fields. Nutrients live on reusable food definitions and are calculated in a native embedded Base in each new log. Calculated columns are read-only; edit the portion or the source food. Source edits, renames and moves update the open embedded Base without rewriting its formulas or copied nutrients.

This is a breaking storage change. Update TPS GCM to 11.4.0 first; Health refuses creation on older GCM builds. The deprecated createFoodNote=false option now still creates/reuses the required food definition. Health's existing index derives totals read-only; the linked-log persistence writer is removed. GCM hides configured nutrient editors on food logs while keeping food-definition editors available. Custom nutrients and property aliases use the same contract.

Existing notes/Bases are not changed automatically. Commands “Use calculated nutrients in current food log” and “Update current food Base calculations” operate on the selected file with an original-source backup, fresh source/editor/exclusion guards, and no background repair. Conversion preserves IDs, unrelated properties and body text; Base conversion changes only exact prior generated expressions. Old unlinked estimates remain readable and are not converted without a valid source/portion. Inline import leaves unresolved originals intact.

Validation: full declared suite 905 tests, 904 passed, 1 optional live USDA credential-gated skip, 0 failures; separate final production build passed after source/version/docs edits. Final build deployed/reloaded only in Obsidian Plugin Test Vault with GCM 11.4.0. Native food-picker creation: 2 can -> 200 kcal; GCM portion edit: 3 can -> 300 kcal; source edit -> 360 kcal, with the log bytes unchanged. Renaming and moving the source retained live totals. Missing fiber and incompatible units stayed Unknown. Generic GCM creation supplied the same embedded body and stripped copied nutrients before its single initial write. Legacy conversion and exact older Base update passed, retaining user body, ID, custom property, view and custom formula. Repeat conversion was a zero-write no-op. All five settings destinations inspected after reload; no settings saved.

Installed source-to-log navigation with normal consumers enabled: 0 getMarkdownFiles calls, 2 reads, 2 cached reads, 0 creates/modifies/processes, focused visible window (same counts as baseline). Two long tasks of 59/50 ms were observed in the post-change navigation sample; this is not a claim of sub-50-ms total rendering. Creation/source edits include existing consumers: one initial create and no follow-up log writes; whole-app counts are recorded in receipts. No new listener, maintenance writer, poller or scan was added. Existing settings/private-state hashes and enabled states were preserved; synthetic fixtures archived. Physical iPhone acceptance is unverified.

Minimum Obsidian: 1.12.0. Native Bases controls/layout remain Obsidian-owned. An already-open standalone Food & Goals Base can still require reopening after only its linked food definition changes; the embedded log Base queries the food itself and updates live. This release is tested in the test vault and ready for the user's BRAT pull; production was not directly updated.
