# TPS Health 3.3.0

Workouts now get a timed calendar slot when they start, so they can qualify immediately for TishOS scheduled Live Activities once the updated record reaches the app.

- New **Workouts → Calendar properties → Default workout estimate (minutes)**, default 60. It applies to new sessions and uses the configured start and duration/end keys. No fallback aliases or automatic rewriting of existing sessions.
- Set edits preserve the slot. Finishing replaces the estimate with actual elapsed time. Provisional intervals do not inflate Health activity totals or appear as completed workout ends.
- Legacy workout notes receive the configured interval; Daily Note tasks receive `timeEstimate` beside their existing `scheduled` field and replace it on completion.
- The existing native-session GCM timer starts after durable active state but before exercise-plan population.

Minor version for additive configuration. Obsidian **1.12.0+**, desktop and mobile. No breaking mapping/schema migration. Settings keep the existing five destinations and disclosure structure.

## TishOS requirements and limits

Live Activities must be enabled. Scheduled mode needs an explicitly selected Calendar Base view whose filters include the workout and whose timing properties match Health. The schedule lasts for the estimate until completion; an enabled, valid GCM running timer takes priority and can continue beyond that interval. Sync/Relay and iOS execution still determine when TishOS receives and presents the activity. This does not promise an instant background ActivityKit start or enable any TishOS permissions/source choices automatically.

Tested in **Obsidian Plugin Test Vault**, ready for the user's **BRAT pull**. Publication does not install it in production.
