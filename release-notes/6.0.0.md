# TPS Health 6.0.0

This major release removes background jobs and unsupported inline-log consumers. Native whole-note food/activity/workout actions, recipe search, macros and explicit timer actions remain. Minimum Obsidian: 1.12.0.

## Removed work and immediate changes
- Barcode Shortcut mailbox reader, two vault-event registrations, 1.5-second poller and acknowledgement writer: removed (one transport owner → zero).
- Startup pending Describe replay/provider requests and startup workout recovery/timer start: removed (one registered layout-ready hook → zero). Explicit Describe/retry and workout creation remain.
- Display-triggered active-workout persistence: removed. Twenty paired display checks went from 40 persistence attempts to zero, with zero inventories.
- Daily inline food/task chips, legacy whole-vault macro fallback, unused getDailyRollup API, retired Daily Note writers and inline workout timer operations: removed. Existing content remains intact; explicit history review/copy is retained.
- Incoming parent deletion no longer trashes legacy workout children. 100 incoming deletions perform zero reads/mutations and preserve child content. Explicit supported conversion remains separately owned.
- Startup credential migration/saves: removed. Twenty settings loads perform zero storage writes or SecretStorage calls. Existing secret references work; preserved old plaintext-only credentials require explicit configuration.
- Unload during the settings read stops initialization before discovery and API/UI registration. The regression reproduced a late registration before the fix.
- Canonical mutation handles are no longer misclassified through physical property mappings: newly logged food remains in the macro index immediately.

Runtime source: 126 additions, 2,706 deletions, net -2,580 lines. No replacement scheduler, watcher, mailbox, cache or repair loop was added. Native read-only discovery and Navigator metadata updates remain. An unused legacy completion-tracking registration method (layout-ready callback, delayed read and three event registrations) is also deleted; it is not counted as an active before-state owner.

Provider/network transports and camera acquisition are mocked. Temporary mappings and roots were restored. These service checks are not iPhone touch/keyboard acceptance.

The final 6.0.0 manifest was reloaded. Source stayed byte-identical and the fixture moved to _archive. Native UI verification showed the Health dashboard, Log food, Log activity, Start workout, Create recipe, macro and activity sections; the original note tab was restored. No external provider request was made.

## Rollout and rollback
Tested in the test vault and ready for the user's BRAT pull. Production was not installed or reloaded. Install the corresponding GCM/Controller/AI cleanup releases together for their retired cross-plugin APIs; AI Gateway 1.0.0 preserves direct requests. Existing notes, credentials, pending workflows and mailbox state are preserved. Downgrading can reactivate automatic processing and writes; stop owners and review preserved state first. Rollback does not overwrite notes.
