# TPS Health 0.3.5

TPS Health `0.3.5` is a backward-compatible performance and reliability patch for exact exercise-name resolution. It preserves every released recognition and exclusion rule while using one supported Obsidian metadata snapshot per visited note.

## Changes

- `findExercise` captures one `getFileCache(file)` result and derives both frontmatter and cached body tags from that snapshot.
- A lookup that visits `k` files now performs `k` metadata-cache calls instead of `2k`, exactly 50% fewer.
- The lookup can no longer combine frontmatter from one metadata generation with tags from a later generation.
- The runtime patch adds one local variable and removes one redundant host call. It adds no persistent cache, timer, listener, monkeypatch, compatibility shim, or fallback.

## Preserved behavior

- Vault order and first-match stopping are unchanged.
- Archive paths and food-identity signals still exclude a note before exercise recognition.
- Cached body tags, `tpsType: health-exercise`, and the configured exercise folder remain the same supported recognition routes.
- Name matching remains normalized and exact; returned fields and defaults are unchanged.
- Official `null` metadata caches still behave as empty frontmatter and empty tags. A note in the configured exercise folder can still match by basename in that state.
- Legacy `kind: exercise` and frontmatter-only tag values outside the configured folder remain unrecognized by this exact lookup. Aligning those routes with interactive search would be a separate behavior change.
- Existing settings, public API, note formats, storage, network behavior, and UI are unchanged.

## Before/after evidence

- The focused permanent regression was added before the source change. Against exact 0.3.4 it failed because each visited file appeared twice in the metadata-call trace; after the change it passes with each path appearing once.
- An actual-class differential compared exact public 0.3.4 with the optimized implementation across six representative and 2,000 seeded randomized stable-cache scenarios.
- Across 23,644 visited files, returned objects had zero mismatches while metadata calls fell from 47,288 to 23,644, exactly 50%.
- Representative cases cover archived and food-like exclusions, tag, `tpsType`, and folder recognition, null/undefined caches, basename defaults, accent/case normalization, legacy kind-only non-recognition, complete misses, and first-match vault order.
- A rotating-cache adversary proves the optimized lookup consumes one coherent generation instead of blending frontmatter and tags from two successive reads.

## Validation

- The final versioned suite, TypeScript check, separate production-mode build, test-vault reload, existing-command smoke check, runtime-state verification, and fresh release-download hashes are recorded in the published release.
- The intentionally credential-gated live USDA integration check remains skipped; this local metadata optimization does not touch providers.
- No food, exercise, workout, setting, provider, or outbound automation is mutated during UI validation.
- Production is not accessed or modified.

## Compatibility and limitations

- Minimum supported Obsidian version remains `1.12.0`.
- No settings or data migration is required.
- This optimization does not change the scan's `O(N)` complexity, cache metadata across calls, or solve pre-existing concurrent find-or-create races. It reduces the supported host calls within each synchronous lookup and makes that lookup internally coherent.
