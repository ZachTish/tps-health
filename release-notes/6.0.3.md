# TPS Health 6.0.3 — Keep new nutrients out of historical food logs

Add a newly tracked nutrient to the food definition and include it in future logs. Existing logs are not backfilled, either on disk or through read-only display. The previous linked-food projection could add a new nutrient to old logs; explicit linked-definition saves could persist it. Projection now uses each existing log's recorded nutrient fields. Creation still uses the current selection and definition. Portion changes recalculate the recorded fields without adding new ones.

Previously recorded nutrient corrections retain their existing linked behavior. Current source is rechecked at the existing atomic write boundary, including concurrent field removals. Temporary read-only definition gaps do not forget a recorded field. Explicit edits to unlinked logs retain ownership of their authored values. Settings explain the policy beside the existing nutrient choices; no new settings schema, date marker, store, queue, scan, watcher or recovery system is added.

Backward-compatible correctness patch, minimum Obsidian **1.12.0**. Existing files are not remediated. Downgrading restores the old behavior that could add new fields to historical logs. Production remains unchanged; this is a BRAT handoff after test-vault validation. Physical iPhone acceptance is separate.
